## 生成顺序

按批次生成，考虑外键依赖关系：

```
批次1: 维度基础数据（无依赖）
  ├── 用户表
  ├── 店铺表
  ├── 类目表
  ├── 品牌表
  ├── 地理区域表
  ├── 支付方式表
  └── 物流公司表

批次2: 维度业务数据（依赖批次1）
  ├── SPU表
  └── SKU表

批次3: 活动 & 优惠券（依赖批次1/2）
  ├── 促销活动表
  └── 优惠券表

批次4: 核心交易数据（依赖前面所有）
  ├── 订单明细表
  ├── 订单活动分摊表
  └── 订单优惠券分摊表

批次5: 履约数据（依赖批次4）
  ├── 支付明细表
  ├── 发货明细表
  ├── 退款明细表
  └── 退款支付明细表

批次6: 互动 & 库存 & 流量（依赖前面）
  ├── 加购表
  ├── 收藏表
  ├── 评价表
  ├── 库存变更表
  ├── 页面访问表
  └── 搜索表
```

## 业务规则

### 1. 时间分布
- **时间范围**: 近一年数据（2025-03-01 至 2026-03-01）
- **促销高峰**: 
  - 618期间（6月1日-6月18日）订单量 × 8
  - 双11期间（11月1日-11月11日）订单量 × 10
  - 双12期间（12月1日-12月12日）订单量 × 5
- **日常分布**: 工作日 vs 周末，白天 vs 夜间有合理差异

### 2. 订单状态流转
```
创建订单
  ├── 15% → 未支付（终态）
  └── 85% → 已支付
        ├── 5% → 支付后取消（终态）
        └── 95% → 已发货
              ├── 2% → 拒收 → 退款
              └── 98% → 已签收
                    └── 10% → 申请退款（约10%退款率）
```

### 3. 优惠分摊规则
- **活动参与率**: 40%订单参与促销活动
- **优惠券使用率**: 40%订单使用优惠券
- **分摊逻辑**: 按订单金额比例分摊到各个明细行

### 4. 库存扣减逻辑
```
下单 → 锁定库存
  ├── 支付成功 → 扣减库存，释放锁定
  ├── 支付超时/取消 → 释放锁定，恢复可用
  └── 退款成功 → 恢复库存（退货场景）
```

### 5. 数据关联规则
- 每个订单必须有合法的用户、店铺、SKU
- 评论必须关联已签收的订单，且评论时间在签收时间之后
- 退款必须关联已支付的订单
- 支付必须关联已创建的订单，且时间在订单之后
- 发货必须在支付之后

### 6. 脱敏规则
- **手机号**: 138****8888 格式
- **邮箱**: k***@gmail.com 格式
- **地址**: 保留省市，详细地址模糊化
- **姓名**: 张**，李** 格式

## 实现要点

### 技术选型
- **异步框架**: asyncio + asyncmy
- **数据生成**: faker（生成真实中文数据）
- **批量插入**: 每批次 1000-5000 条，减少数据库往返
- **并发控制**: 使用信号量控制并发数（默认 10）

### 性能优化
1. **预加载维度数据**: 先生成所有维度数据并缓存，避免重复查询
2. **批量插入**: 使用 `INSERT INTO ... VALUES (), (), ()` 批量插入
