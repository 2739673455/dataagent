## 业务规则

### 1. 时间分布
- **时间范围**: 近三年数据（三年前 至 今天）
- **促销高峰**: 
  - 618期间（6月1日-6月18日）订单量 × 8
  - 双11期间（11月1日-11月11日）订单量 × 10
  - 双12期间（12月1日-12月12日）订单量 × 5
- **日常分布**: 工作日 vs 周末，白天 vs 夜间有合理差异

### 2. 订单状态流转
```
创建订单
  ├── 15% → 未支付（终态）
  └── 85% → 已支付
        ├── 5% → 支付后取消（终态）
        └── 95% → 已发货
              ├── 2% → 拒收 → 退款
              └── 98% → 已签收
                    └── 10% → 申请退款（约10%退款率）
```

### 3. 优惠分摊规则
- **活动参与率**: 40%订单参与促销活动
- **优惠券使用率**: 40%订单使用优惠券
- **分摊逻辑**: 按订单金额比例分摊到各个明细行
- **重叠逻辑**: 活动和优惠券可重叠

### 4. 库存扣减逻辑
```
下单 → 锁定库存
  ├── 支付成功 → 扣减库存，释放锁定
  ├── 支付超时/取消 → 释放锁定，恢复可用
  └── 退款成功 → 恢复库存（退货场景）
```

### 5. 数据关联规则
- 用户口径：每天独立生成用户快照，不做跨天累计约束，仅要求最后一天用户总量达到 30,000
- 批次1静态维度：只读取 `core/generators/seeds/*.json` 冻结种子，不在运行时随机生成
- 静态维度快照：在整个日期范围内每天平铺同一版主数据，仅 `etl_date` 不同
- 每个订单必须有合法的用户、店铺、SKU
- 评论必须关联已签收的订单，且评论时间在签收时间之后
- 退款必须关联已支付的订单
- 支付必须关联已创建的订单，且时间在订单之后
- 发货必须在支付之后

### 6. 脱敏规则
- **手机号**: 138****8888 格式
- **邮箱**: k***@gmail.com 格式
- **地址**: 保留省市，详细地址模糊化
- **姓名**: 张**，李** 格式

## 实现要点

### 技术选型
- **数据库操作**: SQLAlchemy
- **静态主数据**: 本地 JSON 冻结种子
- **批量插入**: 每批次 1000-5000 条，减少数据库往返

### 批次1来源
- **店铺/类目/品牌**: 基于真实电商平台公开信息整理的冻结种子
- **支付方式/物流公司**: 基于主流电商平台常见能力与行业公开名单整理
- **地理区域**: 基于中国省/市/区真实行政区划名称整理
- **种子维护**: 直接编辑 `core/generators/seeds/*.json`

## 使用方式

```bash
# 1. 安装依赖
uv sync

# 2. 初始化数据库（创建表结构）
uv run core/init_db.py

# 3. 生成数据
uv run -m core.generators.main
```
