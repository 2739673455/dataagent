# 02. Identity：身份认证与数据授权

Identity 提供登录认证、用户管理、Doris 角色与数据权限管理，并为其他模块提供用户身份、资产访问策略和查询凭据。账号注销时，Identity 管理账号与任务状态，Workflows 协调资源清理。

## 1. 提供哪些功能

```text
Identity：身份认证与数据授权
├── 登录认证（登录页面及已登录用户）
│   ├── 使用用户名或邮箱登录
│   ├── 刷新令牌与退出登录
│   ├── 修改自己的密码
│   └── 获取当前用户信息
├── 用户管理（平台管理员）
│   ├── 创建与查询用户
│   ├── 修改用户名和邮箱
│   ├── 重设密码与设置管理员
│   ├── 绑定或清除 Doris 角色
│   └── 通过引导脚本初始化管理员
├── Doris 角色管理（平台管理员）
│   ├── 创建和删除角色及对应查询账号
│   ├── 查看受管理角色与 Doris 已有角色
│   ├── 查看工作组
│   └── 设置或清除默认角色
├── 数据权限管理（平台管理员）
│   ├── 查看、授予和撤销库／表／列的 SELECT 权限
│   └── 查看、创建和删除行级策略
├── 跨模块身份与授权（HTTP 依赖、Assistant、Metadata、Query）
│   ├── 验证访问令牌
│   ├── 检查管理员资格与分析资格
│   ├── 获取资产访问策略
│   └── 解析 Doris 查询身份与凭据
└── 注销状态管理（Workflows）
    ├── 禁用账号与撤销令牌
    ├── 创建注销任务
    ├── 领取任务与延长租约
    ├── 记录失败与重试时间
    └── 完成账号删除
```

密码哈希、令牌轮换、认证限流、凭据加密和权限指纹为上述功能提供基础支持。

## 2. 如何使用

### 2.1 页面、HTTP 与命令行入口

**登录认证**

| 操作 | HTTP 入口 | 身份要求 |
| --- | --- | --- |
| 登录 | `POST /api/v1/auth/login` | 用户名或邮箱及密码 |
| 刷新令牌 | `POST /api/v1/auth/refresh` | 有效 Refresh Token |
| 退出登录 | `POST /api/v1/auth/logout` | 要撤销的 Refresh Token |
| 获取当前用户 | `GET /api/v1/auth/me` | 有效 Access Token |
| 修改密码 | `POST /api/v1/auth/change-password` | 有效 Access Token 及当前密码 |

**用户管理**

页面入口：管理中心 → 用户账号管理。以下操作均要求平台管理员身份。

| 操作 | HTTP 入口 |
| --- | --- |
| 创建用户 | `POST /api/v1/admin/users` |
| 查询用户 | `GET /api/v1/admin/users` |
| 修改用户 | `PUT /api/v1/admin/users/{user_id}` |
| 受理用户注销 | `DELETE /api/v1/admin/users/{user_id}` |

**Doris 角色管理**

页面入口：管理中心 → Doris 角色管理。以下操作均要求平台管理员身份。

| 操作 | HTTP 入口 |
| --- | --- |
| 查看受管理角色 | `GET /api/v1/admin/doris-roles` |
| 查看 Doris 已有角色 | `GET /api/v1/admin/doris-roles/existing` |
| 查看工作组 | `GET /api/v1/admin/doris-roles/workload-groups` |
| 创建角色及查询账号 | `POST /api/v1/admin/doris-roles` |
| 删除角色及查询账号 | `DELETE /api/v1/admin/doris-roles/{role}` |
| 设置默认角色 | `PUT /api/v1/admin/doris-roles/{role}/default` |
| 清除默认角色 | `DELETE /api/v1/admin/doris-roles/default` |

**数据权限管理**

在 Doris 角色管理页面选择角色后操作。以下接口均要求平台管理员身份。

| 操作 | HTTP 入口 |
| --- | --- |
| 查看有效 SELECT 权限 | `GET /api/v1/admin/doris-roles/{role}/select-grants` |
| 授予 SELECT 权限 | `POST /api/v1/admin/doris-roles/{role}/select-grants` |
| 撤销指定 SELECT 权限 | `DELETE /api/v1/admin/doris-roles/{role}/select-grants` |
| 撤销当前数据库的全部 SELECT 权限 | `DELETE /api/v1/admin/doris-roles/{role}/select-grants/all` |
| 查看行级策略 | `GET /api/v1/admin/doris-roles/{role}/row-policies` |
| 创建行级策略 | `POST /api/v1/admin/doris-roles/{role}/row-policies` |
| 删除行级策略 | `DELETE /api/v1/admin/doris-roles/{role}/row-policies` |

**初始化管理员**

在部署环境中准备引导凭据后执行：

```bash
uv run -m scripts.bootstrap_admin
```

引导脚本读取 `ADMIN_USERNAME`、`ADMIN_EMAIL` 和 `ADMIN_PASSWORD`，用户名和邮箱可通过命令行覆盖；已有账号必须通过身份和密码匹配检查。

典型配置顺序：

1. 初始化管理员。
2. 创建 Doris 角色和查询账号。
3. 配置 SELECT 权限及行级策略。
4. 创建用户并绑定角色；设置默认角色后，未指定角色的新用户自动绑定该角色。

### 2.2 其他模块直接调用 IdentityService

| 内容 | 导入位置 |
| --- | --- |
| 公开服务 | `app.identity` |
| 返回类型 | `app.identity.contracts` |
| 业务异常 | `app.identity.errors` |

应用启动时创建 `IdentityService`，将实例注入需要它的服务。调用方直接调用方法，数据库会话由 Identity 内部管理。

| 方法 | 输入 | 结果 |
| --- | --- | --- |
| `authenticate(access_token)` | Access Token 字符串 | 返回 `AuthenticatedUser` 用户快照 |
| `require_admin(user)` | 已认证用户快照 | 校验管理员资格，失败抛出权限异常；同步方法 |
| `require_analysis_access(user)` | 已认证用户快照 | 确认用户绑定了平台记录的查询身份 |
| `asset_policy(user_id)` | 服务端确认的用户 ID | 返回本次操作的 `AssetAccessPolicy` |
| `resolve_query_principal(user_id)` | 服务端确认的用户 ID | 返回 `ResolvedQueryPrincipal` 查询身份 |

初始化示例，`auth_postgres` 和 `doris_admin` 为应用已创建的数据库管理器：

```python
from app.identity import IdentityService

identity = IdentityService(postgres=auth_postgres, doris=doris_admin)
```

在异步请求或业务方法中，使用已注入的 `identity`：

```python
user = await identity.authenticate(access_token)
await identity.require_analysis_access(user)

# 检索操作取得本次使用的资产权限快照。
policy = await identity.asset_policy(user.id)
```

Query 在执行 SQL 前直接调用 `await identity.resolve_query_principal(user_id)`。结果包含角色名、查询用户名、解密后的密码、Workload Group 和权限指纹，供服务端查询连接池使用。查询凭据仅用于服务端建连。

HTTP 路由按操作选择 `app/dependencies.py` 中的依赖：

| 依赖 | 检查内容 |
| --- | --- |
| `CurrentUserDep` | Access Token、账号启用状态和认证版本 |
| `AdminUserDep` | 当前用户认证通过，且具有平台管理员标记 |
| `AnalysisUserDep` | 当前用户认证通过，且绑定了平台记录的查询身份 |

`require_analysis_access` 确认的是分析入口资格；具体查询时，`resolve_query_principal` 会重新读取账号状态和 Doris 实际授权。

### 2.3 注销工作流调用

`app.identity.UserDeletionStateService` 提供注销流程所需的状态操作：

| 方法 | 职责 |
| --- | --- |
| `request` | 在同一事务中禁用用户、撤销刷新令牌并创建 pending 任务 |
| `execution_lock` | 获取用户级执行锁 |
| `claim_due_user_ids` | 领取到期任务并设置租约 |
| `extend_claim` | 延长任务租约 |
| `record_failure` | 保存错误和下次尝试时间 |
| `complete` | 删除用户记录并将任务标记为 completed |

注销流程：

1. Workflows 受理管理员请求，调用 `request` 禁用账号并创建任务。
2. 事务提交后投递清理任务。
3. Worker 取得用户执行锁，确认任务仍待处理。
4. 清理会话、Checkpoint、召回记录和沙箱。
5. 调用 `complete` 删除用户记录，将任务标记为 completed。

| 运行情况 | 处理方式 |
| --- | --- |
| 投递或执行失败 | 保留 pending 状态，由定时扫描领取到期任务重试 |
| 多个 Worker 领取任务 | 通过任务租约限制重复领取 |
| 同一用户重复触发清理 | 通过用户执行锁保证清理互斥 |

## 3. 关键业务规则

### 3.1 平台用户、管理员与查询角色

| 身份或配置 | 作用与关系 |
| --- | --- |
| 平台用户 | 用于登录和确认资源归属，每个用户最多绑定一个 Doris 角色 |
| 平台管理员 | 拥有平台管理能力；执行数据分析时仍需绑定查询角色并遵守数据权限 |
| 受管理的 Doris 角色 | 可由多个用户共享，每个角色对应一个查询账号和 Workload Group |
| 默认角色 | 用于创建时未指定角色的新用户；修改后，已有用户的绑定保持原值 |

账号与角色操作规则：

| 操作 | 规则 |
| --- | --- |
| 保存用户名或邮箱 | 去除首尾空白、转换大小写后检查唯一性 |
| 设置密码 | 最低长度由 `auth.password_min_length` 配置，当前为 6 字符，上限为 128 字符 |
| 创建角色 | 检查指定工作组 |
| 删除角色 | 检查平台用户引用，成功删除后失效对应查询连接池 |
| 修改或注销管理员 | 保护最后一个活跃管理员 |
| 受理注销 | 禁止管理员注销自己 |

### 3.2 资产可见性与 SQL 执行权限

资产按数据源、数据库、表和列分层。`AssetAccessPolicy` 提供两种判断：

| 方法 | 含义 |
| --- | --- |
| `allows(asset)` | 某项授权完整覆盖目标资产 |
| `is_visible(asset)` | 目标资产本身或其下级资产存在授权，可用于目录呈现 |

例如，只授权 `orders.amount` 时，表 `orders` 可以出现在可见目录中，`amount` 字段可被召回；这项列授权并不授予整张表的读取权。

**各阶段的权限检查**

| 阶段 | 检查方式 |
| --- | --- |
| 元数据检索 | Metadata 使用资产策略过滤检索范围和结果 |
| 查询经验召回 | 按经验引用的资产过滤结果 |
| SQL 执行 | 使用角色对应的 Doris 查询账号，由 Doris 检查表、列权限与行级策略 |

一次 SQL 查询按以下顺序执行：

1. Query 解析当前查询身份。
2. SQL Guard 检查只读语句、Catalog 和关联规则等约束。
3. 使用解析出的查询账号连接 Doris 执行。

**查询身份与授权快照**

- 每次独立的授权操作读取 Doris 当前有效权限，同一次操作复用所得快照。
- 查询账号只绑定平台配置的业务角色，直接授予该账号的权限也计入有效权限。
- 账号带有额外业务角色、管理权限或无法解析的授权时，身份解析失败。

**权限管理的生效范围**

| 操作或情况 | 行为 |
| --- | --- |
| 查看权限 | 展示查询账号的有效 SELECT 权限 |
| 授予或撤销权限 | 修改角色上的授权 |
| 撤权后仍有直接授权或上级授权 | 目标可能仍可访问，接口会报告该情况 |
| 修改全局或 Catalog 授权 | 需在 Doris 中处理 |

### 3.3 令牌与账号状态变化

| 操作 | 生效行为 |
| --- | --- |
| 登录 | 校验账号和密码，签发 Access Token 与 Refresh Token |
| 刷新 | 消费当前 Refresh Token，签发新令牌对 |
| 重复使用已消费的 Refresh Token | 撤销对应令牌家族并拒绝请求 |
| 退出登录 | 撤销对应刷新令牌家族；已签发 Access Token 仍按有效期和账号状态校验 |
| 修改密码 | 更新认证版本并撤销该用户的刷新令牌，使已有登录凭据失效 |
| 管理员更新用户 | 更新认证版本并撤销该用户的刷新令牌，使已有登录凭据失效 |
| 受理注销 | 禁用账号、撤销刷新令牌并记录清理任务，后续认证被拒绝 |

注销状态的含义：

- 请求受理后，账号禁用，清理任务处于 pending 状态。
- 重复受理保留已有任务状态，清理失败由后台重试。
- 任务完成后，删除用户记录，任务标记为 completed。

账号状态变更作用于后续认证，运行中的跨进程任务由各自执行与取消机制管理。

### 3.4 权限指纹与缓存

`authorization_fingerprint` 表示查询身份、有效授权和行策略内容的摘要。

| 对象 | 使用规则 |
| --- | --- |
| 查询经验及召回缓存 | 按角色和权限指纹匹配，并结合经验状态、元数据版本及缓存有效期决定是否复用 |
| 实际 SQL | 每次使用当前查询身份重新执行 |
| 元数据示例和取值索引 | 由平台管理连接构建，检索时按资产可见范围过滤；预先构建的值未逐次套用用户的行级策略 |

| 调用入口 | 会话与事务 |

### 4.2 数据归属

| 数据 | 保存位置 |
| --- | --- |
| 用户资料、密码哈希、管理员标记、角色绑定、认证版本 | PostgreSQL `auth` 的 `User` |
| 刷新令牌摘要、家族、有效期及撤销关系 | PostgreSQL `auth` 的 `RefreshToken` |
| 角色配置、查询账号、加密密码、工作组、默认标记、权限指纹 | PostgreSQL `auth` 的 `DorisQueryIdentity` |
| 注销状态、尝试次数、领取时间及错误 | PostgreSQL `auth` 的 `UserDeletionTask` |
| 实际角色、查询账号、SELECT 授权和行级策略 | Doris |
| 本次操作的用户快照、资产策略和查询身份 | 内存中的公开值对象 |

### 4.3 认证与凭据

**密码哈希**

密码使用 Argon2id 哈希，在线程中计算，并通过进程共享的哈希器限制并发。账号不存在时执行虚拟哈希校验，缩小登录失败的耗时差异。

**令牌**

| 类型 | 当前配置有效期 | 校验与维护方式 |
| --- | --- | --- |
| Access Token | 15 分钟 | 使用 JWT，每次请求检查签名、算法、签发者、时效、账号启用状态及 `auth_version` |
| Refresh Token | 30 天 | 轮换与撤销通过数据库事务和行锁完成 |

有效期配置位于 [app_config.yaml](../conf/app_config.yaml)。

**查询凭据**

查询密码使用 Fernet 加密，主密钥来自 `DORIS_CREDENTIAL_ENCRYPTION_KEY`。解密结果只用于服务端连接，日志和管理响应不返回密码。更换主密钥会影响现存密文的解密。

**认证限流**

登录和刷新限流使用共享 Redis，超限返回 429 和 `Retry-After`：

| 维度 | 60 秒窗口上限 | 活跃键上限 |
| --- | --- | --- |
| 登录 IP | 30 次 | 10,000 |
| 登录标识 | 10 次 | 50,000 |
| 刷新 IP | 60 次 | 10,000 |

客户端 IP 来自 ASGI 连接信息。代理部署需正确配置可信代理，使连接地址能够反映实际调用方；Redis 故障时认证限流服务报错。

### 4.4 授权观察、事务与跨存储操作

**授权观察流程**

1. 获取查询身份行锁，同角色的授权观察串行执行。
2. 读取查询账号的 `SHOW GRANTS` 和行策略。
3. 规范化授权内容，计算 SHA-256 权限指纹。
4. 保存指纹并提交短事务。

| 指纹处理 | 内容 |
| --- | --- |
| 参与计算 | 身份绑定、授权范围、行策略作用域、组合方式和谓词 |
| 忽略差异 | 行策略名称、内部 ID 和返回顺序 |

事务在 SQL 执行、ES 检索或模型调用前结束。读取快照后发生的外部权限变更，由 Doris 在实际执行时处理。

**跨存储操作**

角色和权限管理涉及 Doris 与 PostgreSQL 两套存储：

| 操作或情况 | 处理方式 |
| --- | --- |
| 创建角色失败 | 尝试清理已创建资源 |
| 删除角色 | 先移除 Doris 查询账号和角色，再删除平台配置 |
| 操作中途失败 | 保留可重试状态，按实际完成阶段继续处理 |
| Doris DDL 或授权变更已执行 | 变更独立生效；后续 PostgreSQL 或状态读取失败时，需要核对两端实际状态 |

**SQL 构造与校验**

| 对象 | 处理方式 |
| --- | --- |
| 数据库标识符 | 仓储通过数据库方言引用 |
| 用户名、密码等值 | 通过驱动参数转义 |
| 行策略表达式 | 权限服务检查结构，Doris 校验字段和执行语义 |

## 5. 异常与排障

HTTP 业务错误使用 `application/problem+json`，可结合响应中的错误类型和详情定位。

| 现象 | 优先检查 |
| --- | --- |
| 登录失败 | 用户名或邮箱、密码、账号启用状态 |
| Token 被拒绝 | 有效期、认证版本；是否已改密或被管理员更新 |
| 刷新令牌重放错误 | 客户端是否并发刷新或继续使用已消费的令牌；重新登录 |
| 返回 429 | 响应中的 `Retry-After`、登录 IP 和标识限流 |
| 能登录但无法进入分析 | 用户是否绑定角色，平台是否保存了对应查询身份 |
| 查询身份解析失败 | 加密密钥、Doris 查询账号、角色绑定、有效授权及管理连接权限 |
| SQL 权限或资源组错误 | 查询账号的实际 SELECT／行权限、Workload Group 及 Doris 返回的错误 |
| 撤权后仍提示有访问权 | 查询账号直接授权、数据库／Catalog／全局等上级授权 |
| 角色删除失败 | 平台用户引用，以及 Doris 用户、角色和平台配置的实际删除进度 |
| 注销长时间未完成 | pending 任务错误、Worker、会话执行锁、沙箱清理状态及到期重试 |

角色或权限修改失败时，先重新读取 Doris 和平台配置的实际状态，再决定重试步骤。

注销清理失败时，按以下顺序排查：

1. 查看 `UserDeletionTask` 的最后错误、尝试次数和下次领取时间。
2. 结合 Worker 日志定位失败步骤。
3. 会话锁忙时等待运行结束；存储或沙箱故障先修复对应资源。
4. 由到期扫描重新投递任务。

任务仍处于 pending 时，账号保持禁用。
