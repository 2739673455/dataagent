# 02. Identity：身份认证与数据授权

Identity 提供登录认证、用户管理、Doris 角色与数据权限管理，并为其他模块提供用户身份、资产访问策略和查询凭据。账号注销时，Identity 管理账号与任务状态，Workflows 协调资源清理。

## 1. 提供哪些功能

| 功能 | 提供的能力 | 使用方 |
| --- | --- | --- |
| 登录认证 | 用户名或邮箱登录、刷新令牌、退出登录、修改密码、获取当前用户 | 登录页面及已登录用户 |
| 用户管理 | 创建和查询用户、修改用户名和邮箱、重设密码、设置管理员、绑定或清除 Doris 角色、初始化管理员 | 平台管理员、引导脚本 |
| Doris 角色管理 | 创建和删除角色及查询账号、查看受管理角色和 Doris 已有角色、查看工作组、设置或清除默认角色 | 平台管理员 |
| 数据权限管理 | 查看、授予和撤销库／表／列的 SELECT 权限，查看、创建和删除行级策略 | 平台管理员 |
| 跨模块身份与授权 | 验证访问令牌、检查管理员和分析资格、获取资产策略、解析 Doris 查询身份 | HTTP 依赖、Assistant、Metadata、Query |
| 注销状态管理 | 禁用账号、撤销令牌、创建注销任务、领取和续租任务、记录失败、完成账号删除 | Workflows |

密码哈希、令牌轮换、认证限流、凭据加密和权限指纹支撑上述功能，具体实现见第 4 节。

## 2. 如何使用

### 2.1 页面、HTTP 与命令行入口

| 操作 | 入口 | 身份要求 |
| --- | --- | --- |
| 登录、刷新、退出 | `/api/v1/auth/login`、`/api/v1/auth/refresh`、`/api/v1/auth/logout` | 账号密码或 Refresh Token |
| 获取当前用户、修改密码 | `/api/v1/auth/me`、`/api/v1/auth/change-password` | 有效 Access Token；改密还需当前密码 |
| 创建、查询、修改、注销用户 | 管理中心 → 用户账号管理；`/api/v1/admin/users` | 平台管理员 |
| 管理角色、默认角色和查询权限 | 管理中心 → Doris 角色管理；`/api/v1/admin/doris-roles` 及其子路由 | 平台管理员 |
| 初始化管理员 | `uv run -m scripts.bootstrap_admin` | 部署环境中的引导凭据 |

用户管理使用 `GET /users` 查询、`POST /users` 创建，以及 `PUT /users/{user_id}` 修改、`DELETE /users/{user_id}` 受理注销，路径前缀为 `/api/v1/admin`。角色的 SELECT 权限通过 `/doris-roles/{role}/select-grants` 查询、授予和撤销；行级策略通过 `/doris-roles/{role}/row-policies` 查询、创建和删除，对应方法均为 GET、POST、DELETE。

引导脚本读取 `ADMIN_USERNAME`、`ADMIN_EMAIL` 和 `ADMIN_PASSWORD`，用户名和邮箱可通过命令行覆盖；已有账号必须通过身份和密码匹配检查。

典型配置顺序：初始化管理员 → 创建 Doris 角色和查询账号 → 配置 SELECT 权限及行级策略 → 创建用户并绑定角色。默认角色可用于后续新用户的自动绑定。

### 2.2 其他模块直接调用 IdentityService

公开服务从 `app.identity` 导入，返回类型从 `app.identity.contracts` 导入，业务异常从 `app.identity.errors` 导入。应用启动时创建 `IdentityService`，将实例注入需要它的服务。调用方直接调用方法，数据库会话由 Identity 内部管理。

| 方法 | 输入 | 结果 |
| --- | --- | --- |
| `authenticate(access_token)` | Access Token 字符串 | 返回 `AuthenticatedUser` 用户快照 |
| `require_admin(user)` | 已认证用户快照 | 校验管理员资格，失败抛出权限异常；同步方法 |
| `require_analysis_access(user)` | 已认证用户快照 | 确认用户绑定了平台记录的查询身份 |
| `asset_policy(user_id)` | 服务端确认的用户 ID | 返回本次操作的 `AssetAccessPolicy` |
| `resolve_query_principal(user_id)` | 服务端确认的用户 ID | 返回 `ResolvedQueryPrincipal` 查询身份 |

初始化示例，`auth_postgres` 和 `doris_admin` 为应用已创建的数据库管理器：

```python
from app.identity import IdentityService

identity = IdentityService(postgres=auth_postgres, doris=doris_admin)
```

在异步请求或业务方法中，使用已注入的 `identity`：

```python
user = await identity.authenticate(access_token)
await identity.require_analysis_access(user)

# 检索操作取得本次使用的资产权限快照。
policy = await identity.asset_policy(user.id)
```

Query 在执行 SQL 前直接调用 `await identity.resolve_query_principal(user_id)`。结果包含角色名、查询用户名、解密后的密码、Workload Group 和权限指纹，供服务端查询连接池使用。查询凭据仅用于服务端建连。

HTTP 路由按操作选择 `app/dependencies.py` 中的依赖：

| 依赖 | 检查内容 |
| --- | --- |
| `CurrentUserDep` | Access Token、账号启用状态和认证版本 |
| `AdminUserDep` | 当前用户认证通过，且具有平台管理员标记 |
| `AnalysisUserDep` | 当前用户认证通过，且绑定了平台记录的查询身份 |

`require_analysis_access` 确认的是分析入口资格；具体查询时，`resolve_query_principal` 会重新读取账号状态和 Doris 实际授权。

### 2.3 注销工作流调用

`app.identity.UserDeletionStateService` 提供注销流程所需的状态操作：

| 方法 | 职责 |
| --- | --- |
| `request` | 在同一事务中禁用用户、撤销刷新令牌并创建 pending 任务 |
| `execution_lock` | 获取用户级执行锁 |
| `claim_due_user_ids`、`extend_claim` | 领取到期任务、设置和延长租约 |
| `record_failure` | 保存错误和下次尝试时间 |
| `complete` | 删除用户记录并将任务标记为 completed |

管理员注销请求经 Workflows 受理，在事务提交后投递任务。Worker 取得用户执行锁、确认任务待处理后，依次清理会话、Checkpoint、召回记录和沙箱，再调用 `complete`。投递或执行失败时保留 pending 状态，由定时扫描领取到期任务重试；任务租约限制重复领取，执行锁保证同一用户的清理互斥。

## 3. 关键业务规则

### 3.1 平台用户、管理员与查询角色

- 平台用户用于登录和确认资源归属，每个用户最多绑定一个 Doris 角色。
- 多个用户可以共享角色；每个受管理角色对应一个查询账号和 Workload Group。
- 管理员标记赋予平台管理能力。管理员执行数据分析时，也需要绑定查询角色并遵守其数据权限。
- 默认角色只用于创建时未指定角色的新用户。修改默认角色后，已有用户的绑定保持原值。
- 创建角色时检查工作组；删除角色前检查平台用户引用，成功删除后失效对应查询连接池。
- 系统保护最后一个活跃管理员，注销入口禁止管理员注销自己。

用户名和邮箱统一去除首尾空白并转换大小写，再进行唯一性检查。密码最低长度由 `auth.password_min_length` 配置，当前为 6 字符，上限为 128 字符。

### 3.2 资产可见性与 SQL 执行权限

资产按数据源、数据库、表和列分层。`AssetAccessPolicy` 提供两种判断：

| 方法 | 含义 |
| --- | --- |
| `allows(asset)` | 某项授权完整覆盖目标资产 |
| `is_visible(asset)` | 目标资产本身或其下级资产存在授权，可用于目录呈现 |

例如，只授权 `orders.amount` 时，表 `orders` 可以出现在可见目录中，`amount` 字段可被召回；这项列授权并不授予整张表的读取权。

Metadata 使用资产策略过滤检索范围和结果，查询经验按其引用资产过滤。**SQL 执行使用角色对应的 Doris 查询账号，表、列权限与行级策略由 Doris 在执行时检查。** Query 先解析查询身份，再通过 SQL Guard 检查只读语句、Catalog 和关联规则等约束，最后使用解析出的查询账号连接 Doris 执行。

每次独立的授权操作读取 Doris 当前有效权限，同一次操作复用所得快照。查询账号必须只绑定平台配置的业务角色；直接授予该账号的权限也计入有效权限。账号带有额外业务角色、管理权限或无法解析的授权时，身份解析会失败。

权限页面展示查询账号的有效 SELECT 权限，授权和撤权操作修改角色。直接授权或上级授权可能使撤权后的目标仍可访问，接口会报告该情况；全局或 Catalog 授权需在 Doris 中处理。

### 3.3 令牌与账号状态变化

| 操作 | 生效行为 |
| --- | --- |
| 登录 | 校验账号和密码，签发 Access Token 与 Refresh Token |
| 刷新 | 消费当前 Refresh Token，签发新令牌对 |
| 重复使用已消费的 Refresh Token | 撤销对应令牌家族并拒绝请求 |
| 退出登录 | 撤销对应刷新令牌家族；已签发 Access Token 仍按有效期和账号状态校验 |
| 修改密码或管理员更新用户 | 更新认证版本并撤销该用户的刷新令牌，使已有登录凭据失效 |
| 受理注销 | 禁用账号、撤销刷新令牌并记录清理任务，后续认证被拒绝 |

注销请求返回表示清理已受理。任务完成后删除用户记录；重复受理保留已有任务状态，失败由后台重试。账号状态变更作用于后续认证，运行中的跨进程任务仍由各自执行与取消机制管理。

### 3.4 权限指纹与缓存

`authorization_fingerprint` 表示查询身份、有效授权和行策略内容的摘要。查询经验及召回缓存按角色和指纹匹配，并结合经验状态、元数据版本及缓存有效期决定是否复用。实际 SQL 每次都使用当前查询身份重新执行。

元数据示例和取值索引由平台管理连接构建，检索过滤采用资产可见范围；这些预先构建的值未逐次套用用户的行级策略。

## 4. 内部实现

### 4.1 目录与职责

```text
app/identity/
├── __init__.py          公开 IdentityService、UserDeletionStateService
├── service.py           用户认证、访问资格与查询身份解析
├── auth/
│   ├── service.py       登录、刷新、退出、改密和管理员引导
│   ├── passwords.py     Argon2id 哈希与并发控制
│   ├── tokens.py        JWT 签发和声明解析
│   └── rate_limit.py    登录和刷新限流
├── accounts/
│   ├── service.py       用户创建、查询、修改和角色绑定
│   ├── validation.py    账号字段、密码和启用状态规则
│   └── deletion.py      注销任务与账号状态事务
├── roles/
│   ├── service.py       Doris 角色、查询账号和默认角色
│   ├── permissions.py   SELECT 权限与行策略管理
│   ├── authorization.py 实时授权观察、资产策略和权限指纹
│   └── credentials.py   查询凭据加解密
├── api/                 HTTP 路由、请求依赖和响应协议
├── repositories/        PostgreSQL、Doris 存储访问

├── contracts.py         跨模块数据契约
└── errors.py            业务异常
```

认证、用户和角色管理 HTTP 服务使用请求级数据库会话，各操作管理自己的事务。跨模块 `IdentityService` 在每次调用中打开短会话，返回脱离 ORM 会话的值对象。连接和客户端由应用生命周期管理。

### 4.2 数据归属

| 数据 | 保存位置 |
| --- | --- |
| 用户资料、密码哈希、管理员标记、角色绑定、认证版本 | PostgreSQL `auth` 的 `User` |
| 刷新令牌摘要、家族、有效期及撤销关系 | PostgreSQL `auth` 的 `RefreshToken` |
| 角色配置、查询账号、加密密码、工作组、默认标记、权限指纹 | PostgreSQL `auth` 的 `DorisQueryIdentity` |
| 注销状态、尝试次数、领取时间及错误 | PostgreSQL `auth` 的 `UserDeletionTask` |
| 实际角色、查询账号、SELECT 授权和行级策略 | Doris |
| 本次操作的用户快照、资产策略和查询身份 | 内存中的公开值对象 |

### 4.3 认证与凭据

密码使用 Argon2id 哈希，在线程中计算，并通过进程共享的哈希器限制并发。账号不存在时执行虚拟哈希校验，缩小登录失败的耗时差异。

Access Token 使用 JWT，每次请求检查签名、算法、签发者、时效、账号启用状态及 `auth_version`。当前配置有效期为 15 分钟；Refresh Token 为 30 天，轮换与撤销通过数据库事务和行锁完成。配置见 [app_config.yaml](../conf/app_config.yaml)。

查询密码使用 Fernet 加密，主密钥来自 `DORIS_CREDENTIAL_ENCRYPTION_KEY`。解密结果只用于服务端连接，日志和管理响应不返回密码。更换主密钥会影响现存密文的解密。

登录和刷新限流使用共享 Redis，超限返回 429 和 `Retry-After`：

| 维度 | 60 秒窗口上限 | 活跃键上限 |
| --- | --- | --- |
| 登录 IP | 30 次 | 10,000 |
| 登录标识 | 10 次 | 50,000 |
| 刷新 IP | 60 次 | 10,000 |

客户端 IP 来自 ASGI 连接信息。代理部署需正确配置可信代理，使连接地址能够反映实际调用方；Redis 故障时认证限流服务报错。

### 4.4 授权观察、事务与跨存储操作

授权观察在身份行锁内读取查询账号的 `SHOW GRANTS` 和行策略，规范化后计算 SHA-256 指纹。指纹包含身份绑定、授权范围、行策略作用域、组合方式和谓词，忽略行策略名称、内部 ID 和返回顺序。

同角色的授权观察串行执行，权限指纹随短事务提交。事务在 SQL 执行、ES 检索或模型调用前结束；读取快照后发生的外部权限变更，由 Doris 在实际执行时处理。

角色创建、删除和授权修改涉及 Doris 与 PostgreSQL 两套存储：创建失败时尝试清理已创建资源；删除先移除 Doris 查询账号和角色，再删除平台配置。中途失败保留可重试状态。Doris 已执行的 DDL 和授权变更独立生效，后续 PostgreSQL 或状态读取失败需要按实际完成阶段处理。

仓储通过数据库方言引用标识符，通过驱动参数转义用户名和密码等值。行策略由权限服务检查表达式结构，再交给 Doris 校验字段和执行语义。

## 5. 异常与排障

HTTP 业务错误使用 `application/problem+json`，可结合响应中的错误类型和详情定位。

| 现象 | 优先检查 |
| --- | --- |
| 登录失败 | 用户名或邮箱、密码、账号启用状态 |
| Token 被拒绝 | 有效期、认证版本；是否已改密或被管理员更新 |
| 刷新令牌重放错误 | 客户端是否并发刷新或继续使用已消费的令牌；重新登录 |
| 返回 429 | 响应中的 `Retry-After`、登录 IP 和标识限流 |
| 能登录但无法进入分析 | 用户是否绑定角色，平台是否保存了对应查询身份 |
| 查询身份解析失败 | 加密密钥、Doris 查询账号、角色绑定、有效授权及管理连接权限 |
| SQL 权限或资源组错误 | 查询账号的实际 SELECT／行权限、Workload Group 及 Doris 返回的错误 |
| 撤权后仍提示有访问权 | 查询账号直接授权、数据库／Catalog／全局等上级授权 |
| 角色删除失败 | 平台用户引用，以及 Doris 用户、角色和平台配置的实际删除进度 |
| 注销长时间未完成 | pending 任务错误、Worker、会话执行锁、沙箱清理状态及到期重试 |

角色或权限修改后遇到错误，先重新读取实际状态，再决定重试步骤。注销清理失败时，结合 `UserDeletionTask` 的最后错误、尝试次数和下次领取时间查看 Worker 日志：会话锁忙时等待运行结束，存储或沙箱故障修复后由到期扫描重新投递。任务仍处于 pending 时，账号保持禁用。
