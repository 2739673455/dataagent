# 02. Identity：预定义用户与数据授权

Identity 只提供 `GET /api/v1/users`，返回用户 ID、用户名和 Doris 角色名。前端直接选择用户，业务 HTTP 请求及 SSE 使用 `X-User-ID`。这是一种身份选择机制，不验证操作者身份；会话、附件和沙箱继续按所选用户 ID 检查归属。

## 1. 预定义身份与初始化

`scripts/bootstrap_users.py` 定义 `ROLES`、`USERS` 及其绑定。目前只有用户 `admin`（ID 1），对应 Doris 角色 `dataagent_admin`，查询账号 `dataagent_admin_query`，工作组 `normal`。

执行 `uv run -m scripts.bootstrap_users` 后：

1. 为角色生成随机密码并加密保存到身份 PostgreSQL；已有记录保留密码。
2. 创建专用 Doris 角色、查询账号，授予 `internal.<配置的业务数据库>.*` 的 `SELECT_PRIV` 和工作组使用权限。
3. 全部角色初始化成功后写入预定义用户。

脚本可重复执行。Doris 创建中断时，重新执行沿用已保存的密码并补齐角色授权；PG 重建后重跑会将专用查询账号密码更新为新保存的值。脚本不删除已有角色或回收人工追加的权限。修改已有身份配置后应重启应用，使运行中的查询连接使用新凭据。不得复用或改动 Doris 自带的全局 `admin` 角色。

当前预定义角色的授权范围是业务库整库查询。后续增加受限角色时，需要同时定义其授权范围及脚本的对应授权语句，不能直接套用整库授权。预定义用户 ID 用于关联会话和沙箱，不应重新分配给其他用户。

开发阶段不提供旧模型迁移。已有旧版用户表时，需按项目初始化流程重建身份表，再执行初始化脚本。脚本不会自动清空旧表或删除已有业务数据。

## 2. 数据与运行时

身份库保留 `users` 和 `doris_query_identities`：前者只存 ID、用户名和角色绑定；后者保存 Doris 查询账号、加密密码、描述、工作组及最近观察到的权限指纹。

用户列表不返回数据库查询密码。查询执行时，`QueryPrincipalService` 按用户读取绑定角色并解密凭据，`DorisQueryClientRegistry` 按角色和凭据复用连接池。业务 SQL 仍经过只读校验，并使用角色专属查询账号执行。

## 3. 实际数据权限

`AuthorizationService` 从 Doris 读取查询账号当前的有效 SELECT 权限及用户、角色行策略，生成资产白名单和指纹；元数据召回只返回所选用户可见的数据。指纹用于检测授权变化，不代替实际授权。

Doris 的全局管理权限仍不能用于业务查询。`admin` 用户在这里表示业务库全部数据可查询，并不具备平台管理接口或 Doris 全局管理权限。若人工修改 Doris 授权，下次读取会反映该变化。

## 4. 前端切换

点击聊天页用户框可展开全部用户，选中即切换；当前用户带选中标记。前端将所选用户 ID 保存在 localStorage，切换时清空聊天缓存、重新加载会话列表并中止本页订阅，旧请求返回不能写入新用户的聊天状态。其他标签页通过 storage 事件同步选择。切换身份不会取消服务器上已开始的分析。

登录、刷新令牌、登出、改密、用户增删改、Doris 角色管理、授权编辑及用户注销任务已移除。
