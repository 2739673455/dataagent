# 02. Identity：用户选择与查询身份

Identity 提供预定义用户列表，将应用用户映射到 Doris 查询账号，并解密查询凭据。会话和文件按应用用户归属，SQL 由对应查询账号执行。

## 1. 提供哪些功能

```text
Identity：用户选择与查询身份
├── 用户选择（前端、HTTP 依赖）
│   ├── 返回用户 ID、用户名和 Doris 角色名
│   ├── 读取 X-User-ID 并确认用户存在
│   └── 切换用户时退出旧会话并加载新用户数据
├── 身份初始化（开发者）
│   ├── 创建预定义用户、Doris 角色及独立查询账号
│   ├── 按角色授予业务查询权限和工作组使用权
│   └── 加密保存查询密码，重复执行沿用已有凭据
├── 查询身份解析（Query）
│   ├── 读取用户与角色查询身份关联
│   ├── 解密密码并返回查询账号
│   └── 分别报告用户不存在和查询身份缺失
└── 凭据维护（开发者）
    ├── 通过 Fernet 密钥保护持久化查询密码
    └── 配合 Doris 授权和应用连接池管理查询访问
```

## 2. 如何使用

### 2.1 页面和 HTTP 入口

| 操作 | 入口 | 结果 |
| --- | --- | --- |
| 读取用户列表 | `GET /api/v1/users` | 用户 ID、用户名与角色名 |
| 选择当前用户 | 聊天页面用户选择器 | 后续请求携带 `X-User-ID` |
| 校验当前用户 | `app.identity.api.dependencies.CurrentUserDep` | 确认请求标识有效且用户存在 |

X-User-ID 是身份选择机制，不是登录凭据，当前使用环境需要信任操作者。mini 不提供密码登录、Token 或角色管理页面。

### 2.2 初始化用户与角色

`scripts/bootstrap_users.py` 使用 RolePreset 和预定义用户集合创建身份。

处理每个角色时，脚本先在身份数据库中保存或读取查询凭据；已有记录沿用原密码。随后创建 Doris 角色，授予业务表 SELECT_PRIV 及 normal 工作组 USAGE_PRIV，创建查询账号、将其密码设为已保存值并绑定角色。全部角色准备完成后，才在一个事务中写入预定义用户关联。

先保存凭据使 Doris 初始化失败后重跑能沿用同一密码。新用户在角色全部就绪后才发布，避免前端选择到初始化尚未完成的新身份；已有用户仍可能受中途授权变更影响。

admin 的表范围为整个配置业务库；受限角色逐表授权。所有角色定位为业务查询身份，不因名字包含 admin 就获得业务写入能力。

初始化跨越 Doris 和 PostgreSQL，不是统一事务。脚本支持重复运行，但授权是追加语义：从预定义清单删除一张表不会自动执行 REVOKE。收缩权限需要显式回收现存授权后再验证实际结果。

### 2.3 查询模块解析凭据

| 使用内容 | 代码位置 |
| --- | --- |
| IdentityService | `app.identity.services.identity` |
| IdentityPGRepo | `app.identity.repositories.identity` |
| DorisCredentialCipher | `app.identity.services.credential` |
| ResolvedQueryPrincipal | `app.identity.models.doris` |

```python
from app.identity.repositories.identity import IdentityPGRepo
from app.identity.services.identity import IdentityService

# auth 和 cipher 由调用方已有资源提供。
async with auth.session() as session:
    identity = IdentityService(IdentityPGRepo(session))
    principal = await identity.get_query_principal(user_id, cipher)
# 在身份数据库会话之外，使用 principal 创建或取得查询连接。
```

返回值包含 role_name、query_user 和 password，仅供服务端连接使用，不返回前端或模型。

## 3. 关键业务规则

### 3.1 预定义角色与查询范围

| 用户         | 角色                   | 查询账号                     | 业务范围          |
| ------------ | ---------------------- | ---------------------------- | ----------------- |
| admin        | dataagent_admin        | dataagent_admin_query        | 整个配置业务库    |
| growth       | dataagent_growth       | dataagent_growth_query       | 增长运营，16 张表 |

### 3.2 查询权限边界

IdentityService 只从身份数据库解析用户与查询身份，不读取 Doris 的 SHOW GRANTS，也不生成资产访问策略。Doris 在实际执行 SQL 时检查查询账号的有效权限；手工修改授权后的访问结果以数据库执行时的判断为准。

| 阶段 | 使用的身份与规则 |
| --- | --- |
| 元数据召回 | 从完整目录检索，不按用户角色过滤 |
| SQL 执行 | 使用当前用户角色的查询账号，由 Doris 检查权限 |
| 会话和附件访问 | 按应用用户 ID 校验资源归属 |

召回到表、字段或指标不构成 SQL 放行凭据。权限拒绝由查询模块识别为 `QueryPermissionDeniedError`，工具返回 `permission_denied`；Explorer 和 Planner 按提示词停止当前任务并提示用户联系管理员。

### 3.3 用户切换与资源归属

前端保存当前用户选择，切换时先退出旧会话路由，再更新身份、清理会话缓存与事件订阅，加载新用户的数据，避免用新身份请求旧会话。已经启动的后台 Run 不因前端切换而改变所有者，也不会自动停止。

会话服务始终使用用户 ID 和会话 ID 组合访问资源。附件下载先检查会话归属，再调用沙箱；沙箱自身还会检查文件是否位于目标会话范围。

## 4. 内部实现

### 4.1 目录与职责

| 位置 | 职责 |
| --- | --- |
| `app/identity/api/` | 用户列表、请求用户选择校验和响应结构 |
| `app/identity/services/identity.py` | 按用户解析查询身份 |
| `app/identity/services/credential.py` | 查询密码加解密 |
| `app/identity/repositories/identity.py` | 用户与查询身份的 PostgreSQL 访问 |
| `app/identity/models/` | 用户、查询身份和解析结果 |
| `app/identity/errors.py` | 用户选择与凭据相关异常 |
| `scripts/bootstrap_users.py` | Doris 与身份数据库的初始化编排 |

### 4.2 数据归属

| 模型                   | 关键字段                                                               | 作用                       |
| ---------------------- | ---------------------------------------------------------------------- | -------------------------- |
| User                   | id、username、doris_role_name                                          | 应用用户及其查询角色       |
| DorisQueryIdentity     | role_name、query_user、encrypted_password、workload_group、description | 角色对应的查询账号和凭据   |
| ResolvedQueryPrincipal | role_name、query_user、password                                        | 一次查询可用的已解密身份   |

User 使用预定义 ID，用户名唯一。角色名引用查询身份记录；查询身份以角色名为主键，查询账号唯一。这个结构允许多个应用用户引用同一角色，而会话依然按各自用户 ID 隔离。

查询凭据是运行资源配置，授权范围来自 Doris。描述字段只负责说明角色用途，不参与权限计算。

### 4.3 身份解析与连接池

IdentityService.get_query_principal 先查 User，再按 doris_role_name 查 DorisQueryIdentity，然后通过 DorisCredentialCipher 解密密码，返回 ResolvedQueryPrincipal。

用户不存在会要求重新选择身份；用户已经存在但角色查询身份缺失，会报告查询身份未配置。两种问题发生在 SQL 执行前，应分别排查用户初始化和角色关联。

DorisQueryClientRegistry 用角色名缓存连接池。密码读取只在需要解析身份时发生，但已有连接池不会因数据库密文变化自动替换。修改查询账号或密码后需要重启应用。
