# 公共模块

## 1. 职责与依赖方向

公共模块提供配置、数据库基础、外部客户端、日志上下文、错误处理和同步脚本的异步入口。它负责资源怎么创建和使用。

业务服务依赖这些能力，应用生命周期负责装配。领域模型归业务模块所有；公共契约只保留实际跨模块共享的类型，例如专业 Agent 的类型集合。

## 2. 配置加载过程

配置首先从进程环境和 dotenv 取得变量，再由 OmegaConf 解析 YAML 中的环境引用，最后交给 Pydantic 构造配置对象。外部已经设置的环境变量可以用于脚本或部署环境注入。

配置模型拒绝未知字段，并约束非空字符串、端口、超时和加密密钥长度等输入。该校验在配置模块加载时发生，早于多数服务初始化。

这意味着一个只准备使用数据库的脚本，也可能因为共享配置中语言模型密钥为空而无法启动。排查启动失败时，先区分配置解析失败、连接初始化失败和业务执行失败，三者还没有到达相同阶段。

| 配置组                  | 主要内容                   | 消费方                       |
| ----------------------- | -------------------------- | ---------------------------- |
| auth_postgresql         | 身份库连接                 | 用户和查询身份服务           |
| meta_postgresql         | 元数据连接                 | 目录、关联和取值水位         |
| langgraph_postgresql    | 会话持久化连接             | 会话仓储及 Checkpoint        |
| doris                   | 管理账号和业务库           | 元数据读取、权限读取和初始化 |
| doris_credentials       | Fernet 密钥                | 查询密码加解密               |
| elasticsearch           | 地址和向量维度             | 语义与取值检索               |
| embedding               | 向量服务模型、密钥和超时   | 导入及召回                   |
| metadata                | 导入 Redis 连接            | 全量和增量互斥               |
| lm_config、agent        | 语言模型集合和角色模型选择 | Agent 装配、标题生成         |
| port、cors_origins、log | 监听、跨域和日志           | Web 基础设施                 |

配置对象在进程中复用，修改配置后重启应用。沙箱资源限制和会话任务周期是代码常量，不属于上述 YAML 配置。

## 3. 敏感值处理

数据库密码、模型密钥和加密密钥通过 SecretStr 保存，普通对象打印会遮盖其内容。客户端建立连接时才显式取出明文。

SecretStr 只降低无意打印的风险，不会自动清理自行构造的日志字符串。ResolvedQueryPrincipal 的密码字段也从默认对象表示中排除。新增日志时不要记录完整配置、连接凭据或请求鉴权头。

查询密码在数据库中的加密与配置对象的遮盖是两回事。前者由 Fernet 完成，后者只是对象表示规则；更换 Fernet 密钥前必须处理已有密文，否则查询身份无法解密。

## 4. PostgreSQL 连接和事务

PostgresClientManager 管理 SQLAlchemy 异步引擎和会话工厂。不同业务数据库使用各自 ORM 基础类，初始化只创建对应数据域的表。

Session 表示一次数据库访问上下文。进入会话上下文负责资源关闭，需要提交的业务操作仍要显式开始事务或提交。仓储执行 SQL，服务决定哪些修改需要共同成功。

常见用法是短事务读取必要状态，离开事务后执行网络或计算，再用新的短事务提交结果。例如查询先读取用户凭据，Doris 流式读取期间不保留身份数据库事务；字段取值同步先读取水位，ES 成功后再提交新水位。

同一个 AsyncSession 不应作为无约束的全局可变对象供多个并行任务同时操作。请求和脚本根据作用域创建会话，连接池负责底层连接复用。

## 5. Doris 连接分工

DorisClientManager 通过异步 MySQL 驱动访问 Doris。连接池使用连接健康检查和定时回收；池等待超时与 SQL 运行超时是不同概念。

管理连接用于读取源表结构、样例和账号授权，初始化脚本也使用管理权限维护角色。用户分析查询由 DorisQueryClientRegistry 创建的角色专属连接池执行。

Registry 以角色名为键缓存连接池，首次使用时根据查询账号和密码创建，后续查询复用。角色凭据改变后，需要重启应用释放缓存；同一个角色名不能在运行中被当成多个动态账号的通用缓存键。

关闭 Registry 时先取出并清空缓存，再逐个释放引擎。具体业务服务只借用连接，不自行销毁公共连接池。

## 6. Checkpoint 和业务会话的区别

LangGraph 使用原生 AsyncPostgresSaver，底层是独立 Psycopg 异步连接池，启动时执行所需初始化。该池与 SQLAlchemy Session 没有共同事务。

会话标题、草稿和删除标记在业务表中；消息和图待执行状态在 Checkpoint 中。因此写入会话标题不会更新图，保存图节点也不代表会话目录操作同步提交。

会话删除服务负责按顺序清理两类状态。应用运行控制使用进程内任务注册表，不通过长期持有 PostgreSQL 行锁来包围模型执行。

## 7. HTTP 与检索客户端

Elasticsearch 使用原生异步客户端。EmbeddingClient 使用 HTTP 客户端请求向量服务，按服务返回的索引恢复向量顺序，并检查条目数量与输入文本数量一致。

向量服务返回的维度必须与 ES 映射一致。配置中的向量维度定义索引要求，不会强制向量模型改变输出。更换模型后需要重新构建已有向量，不能只更新维度数字。

客户端报告传输和协议失败。业务层决定失败如何处理：全量导入依赖全部向量，失败就终止；在线召回允许向量通道失败而继续全文检索，并返回部分失败信息。

## 8. 应用资源生命周期

WebResources 汇总应用级服务。生命周期按创建顺序登记资源，使用 AsyncExitStack 逆序关闭。路由依赖仅取出业务需要的服务，不把整个资源容器传递到每一层。

资源分为三种常见作用域：

| 作用域 | 示例                                   | 释放时机           |
| ------ | -------------------------------------- | ------------------ |
| 应用级 | 数据库引擎、ES、沙箱管理器、Agent 模型 | 应用退出           |
| 调用级 | Session、Doris 连接、临时文件          | 调用完成或异常退出 |
| 任务级 | 标题模型客户端、图流、shell 执行资源   | 后台任务结束或取消 |

维护代码时，资源的创建点应同时能看到其关闭责任。若新增后台任务借用应用资源，应在资源关闭前取消并等待任务，避免关闭后仍有协程访问客户端。

## 9. 错误投影

HTTP 层统一使用 Problem Details 表达错误，包含类型、标题、状态和详情等字段。参数校验、业务异常、HTTP 异常和未知异常由全局处理器处理。

工具调用和 SSE 使用各自传输协议。工具将已知错误转换为模型可理解的文本；SSE 在响应开始后通过 error 事件报告运行失败，不能再改成另一个普通 HTTP 错误响应。

异常日志保留堆栈用于开发排查，用户界面只需要能理解的说明。需要给异常补充上下文时保留原始异常关系，不要把底层失败转换为成功空结果。

## 10. 日志和上下文

ContextVar 保存 request_id、trace_id、用户和请求信息，避免并发协程共享可变全局变量。请求中间件在进入和退出时设置、恢复上下文。

日志支持控制台与 JSONL 文件，按配置滚动。后台执行跨越请求生命周期时，还要用会话 ID、资源键或任务名称关联。一个请求断开不一定意味着其后台 Run 已停止。

## 11. 同步入口与取消

run_async 为同步脚本创建事件循环并执行主协程。Windows 使用 SelectorEventLoop 满足异步 PostgreSQL 客户端要求。

取消是任务控制信号。正常业务异常可以记录或转换，取消需要传播到真正持有外部操作的组件，使其释放连接、关闭流或终止进程。使用宽泛异常捕获时要检查是否会误吞取消。
