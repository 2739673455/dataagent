# 03. Metadata：元数据导入与语义召回

Metadata 保存表、字段和指标的业务目录，建立检索索引，并为 Explorer 管理语义召回上下文。维护入口只有一个脚本的全量和字段取值增量两种模式；Web 不提供元数据管理接口或页面，Celery 不处理元数据导入和索引任务。

## 1. 模块结构与职责

| 组件 | 职责 |
| --- | --- |
| MetaConfig | YAML 结构、字段名、说明、别名、引用和水位配置 |
| MetaImportService | 校验源表、清空重建目录、顺序完成全部索引 |
| MetaIndexService | 字段和指标语义索引、字段取值索引及水位提交 |
| MetaPGRepo | 目录、字段关联和取值同步状态持久化 |
| SourceDorisRepo | 物理结构、示例值、表水位和流式字段值读取 |
| ColumnESRepo、MetricESRepo、ValueESRepo | 三个元数据索引的存储和检索 |
| SemanticResourceRecallService | 授权后的混合检索与上下文补全 |
| SemanticRecallContextService | 召回快照的累计、读取、合并和删除 |

脚本每次运行创建和关闭 PostgreSQL、Doris、Elasticsearch 与 Embedding 客户端。同一数据库中的全量和增量运行通过 PostgreSQL 事务级 advisory lock 互斥，进程退出或连接断开后自动释放；未取得锁的脚本直接失败。独立锁连接覆盖整次运行，数据写入使用另外的短事务。

## 2. YAML 与目录模型

表定义名称、事实表或维表角色、说明和可选水位字段。字段定义说明、别名、是否启用取值索引及可选关联字段；关联表和关联字段必须同时提供。指标定义业务说明、别名和引用字段列表。

导入拒绝空表清单、未知配置字段、重复表名、同表重复字段名、重复指标名、自引用字段及不存在的引用目标。Doris 提供实际字段类型和 UNIQUE KEY 列，脚本校验源表、字段和水位列存在，并按表一次读取所有字段的有限示例值。

PostgreSQL 保存表、字段、指标及字段指标关联。字段/指标的元数据版本和语义索引版本供召回判断索引状态；取值同步状态按字段保存，某个字段失败不会推进其他未完成字段的水位。

## 3. 全量导入流程

全量脚本默认读取项目中的元数据 YAML，也可以指定文件。执行顺序为：

1. 读取并校验 YAML，校验源表结构及引用，准备目录实体和字段示例。
2. 删除并按当前配置重建字段、指标、字段值三个 Elasticsearch 索引。
3. 在 PostgreSQL 事务内清空元数据目录、指标关联、取值同步状态及旧召回快照，写入完整新目录。
4. 为所有字段构建语义索引，再为所有指标构建语义索引。名称、说明和别名规范化去重后直接生成向量并批量写入，不读取旧索引或比较文档差量；写入成功后标记索引就绪。
5. 对启用取值索引的字段分批读取去重取值，写入索引并保存初始水位。

全量导入清理所有原有目录内容，不比较新增、修改和删除差量。配置或源表检查失败时不清理既有目录和索引。正式重建开始后 PostgreSQL 与 Elasticsearch 没有跨库原子事务，失败可能留下部分新数据，重新运行全量脚本即可从清空步骤重建。认证数据和 Doris 业务表不属于清理范围。

## 4. 字段取值增量导入

增量脚本读取数据库中的目录和水位配置，不重新载入 YAML，也不修改字段和指标的语义定义。只处理启用 `index_values` 且所属表配置了 `value_index_cursor_column` 的字段。

每张表一次读取水位最大值并固定本次上界。最大值为空、相等或小于已提交水位时跳过取值扫描并保留旧水位；推进后读取左开右闭的水位区间，分批去重、序列化并按稳定文档 ID 写入 ES。只有索引写入和刷新成功后才提交字段的新水位。

全量导入时空表的水位可以为空；以后出现首批非空水位时，从无下界开始读取至本次上界。没有完成全量索引的字段不能自动改走全量逻辑，增量脚本会报错。未配置水位的表明确跳过。

索引写入失败保留旧水位并记录错误。重跑时可以重复写入之前已写入的部分值，稳定文档 ID 避免重复记录。脚本互斥锁允许重试接管进程中断留下的运行状态。水位字段必须随新增或更新递增；旧水位的迟到记录及源值删除需要全量重建。

字段和指标的名称、说明及别名生成全文和向量检索文档，向量维度必须与 Embedding 服务匹配。字段取值使用全文索引，不逐值生成向量。

## 5. 混合检索与上下文补全

一次 `recall_context` 可以携带稳定 query、1—20 个检索词、字段/指标/取值资源类型，以及每类 1—20 个结果上限。

搜索前，系统读取当前权限和目录，生成资源白名单，加入 ES 查询条件。字段和指标并行执行全文与向量搜索，再用倒数排名融合：看候选在各条搜索结果中的名次，而不是直接相加不同量纲的原始分数。当前 RRF 常数为 60，候选数量通常为目标上限的三倍、最多 60。

服务先加载 PostgreSQL 目录并关闭会话，再进行外部检索；命中后根据这份目录组装资源，丢弃不存在或不在当前可见集合中的键，补充指标依赖字段、已授权主键和一层外键关系。ES 旧文档仍可能影响排名；返回最新目录内容和 `index_status` 不等于已经彻底消除了旧排名影响。

有排名的直接字段及指标依赖字段最多进入 30 个上下文位置；取值所属字段、主键和外键属于补充信息，因此最终字段总数可能超过 30。发生截断会给出标志和 warning；每个返回字段最多展示 3 个示例。

Embedding 失败时，已经成功的全文结果仍可返回，并标记部分失败。字段值或某个搜索通道失败也不必吞掉其他通道的结果。`partial` 描述本次搜索的完整性，`current/stale/missing` 描述索引状态，二者不要混用。

## 6. 召回快照与 query 生命周期

Explorer 往往先找销售指标，再补地区字段，最后确认退款状态。如果每次工具调用都丢掉上一步，模型要不断重复检索。因此系统以用户、Conversation 和稳定 query 累积上下文。

query 是业务键，不是每次换一个说法的日志文本。后续补搜应复用相同 query，仅改变检索词和资源类型。合并时保留更新的元数据版本、较优排名和去重后的来源说明，不把每轮排名重新计算成一个全局分数。

搜索在写锁之外执行；保存时按 query 加锁，读取当前快照再合并，避免并发结果互相覆盖。快照存入 `meta` 数据库，新召回可以追加快照；显式合并或删除会移除相关历史，因此它不是不可删除的审计账本。

| 工具 | 对快照做什么 |
| --- | --- |
| `recall_context` | 检索并累积指定 query 的语义资源 |
| `list_recalls` | 列出当前 Conversation 的最近 query 摘要 |
| `get_recall` | 读取某个 query 的最新累计结果 |
| `merge_recalls` | 把来源 query 的语义资源并入目标，再删除来源 |
| `delete_recalls` | 删除整个 query，或指定表、字段、值、指标；一次调用中 query 不重复 |

## 7. 快照授权边界

Checkpoint 中工具消息主要保存引用，调用模型或展示历史时再按当前权限展开。独立读取会重新取得策略，批量展开会复用同一次操作的读取结果，避免逐条打开数据库会话。

读取或展开已保存的快照时，系统按当前资产访问权限过滤表、字段和指标，已撤销的权限不能通过旧快照继续访问。

删除工具保存的是已存储或已删除 query 的确认信息，后续展开也重新检查权限，不应把旧完整 payload 固定嵌在工具消息中继续暴露。召回运行资源由 `SemanticRecallRuntime` 明确注入，服务组装由模块 providers 完成。

## 8. 运行结果与故障定位

脚本同步执行整个流程，不以“后台任务已提交”作为成功。退出码为零表示全部步骤完成；日志记录配置校验、目录写入、语义索引构建、字段取值数量和水位。

失败时先区分 YAML/源表校验、Embedding、ES 写入和 PostgreSQL 状态提交。增量失败重新执行增量脚本；全量失败重新执行全量脚本。旧召回引用在全量清理后可能找不到记录，需要重新召回。
