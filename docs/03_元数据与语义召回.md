# 03. Metadata：元数据导入与语义召回

Metadata 保存表、字段和指标的业务目录，建立检索索引，并为 Explorer 提供语义召回结果。通过导入脚本执行全量导入或字段取值增量同步。

## 1. 模块结构与职责

| 组件 | 职责 |
| --- | --- |
| MetaConfig | YAML 结构、字段名、说明、别名、引用和水位配置 |
| MetaIndexService | 校验源表、重建目录、字段和指标语义索引、字段取值索引及水位提交 |
| MetaPGRepo | 目录、字段关联和取值水位持久化 |
| SourceDorisRepo | 物理结构、示例值、表水位和流式字段值读取 |
| ColumnESRepo、MetricESRepo、ValueESRepo | 三个元数据索引的存储和检索 |
| SemanticResourceRecallService | 授权后的混合检索与上下文补全 |

脚本通过 Redis 租约锁互斥执行全量和增量导入，未取得锁时直接失败，不初始化数据库等客户端。租约有效期 60 秒，每 20 秒续租；续租失败取消导入。正常退出先关闭 PostgreSQL、Doris、Elasticsearch 与 Embedding 客户端，再按持有者 token 释放锁；进程异常退出后租约自动过期。PostgreSQL 在读取配置、写入目录或提交水位时使用短事务。所有访问同一目录的导入进程必须使用相同的 `metadata.redis_url` 和 PostgreSQL 地址配置。

## 2. YAML 与目录模型

表定义名称、事实表或维表角色、说明和可选水位字段。字段定义说明、别名、是否启用取值索引及可选关联字段；关联表和关联字段必须同时提供。指标定义业务说明、别名和引用字段列表。

导入拒绝未知配置字段、重复表名、同表重复字段名、重复指标名及不存在的引用目标。Doris 提供实际字段类型和 UNIQUE KEY 列，脚本校验源表、字段和水位列存在，并按表一次读取所有字段的有限示例值。

PostgreSQL 保存表、字段、指标及字段指标关联。字段记录上的 `value_index_cursor_value` 只保存已成功提交的取值水位，不保存运行 ID、状态、错误和更新时间；也不维护字段或指标的索引就绪标记。某个字段失败保留其旧水位，已经完成的字段保留新水位。

## 3. 全量导入流程

全量脚本默认读取项目中的元数据 YAML，也可以指定文件。执行顺序为：

1. 读取并校验 YAML，校验源表结构及引用，准备目录实体和字段示例。
2. 删除并按当前配置重建字段、指标、字段值三个 Elasticsearch 索引。
3. 在 PostgreSQL 事务内清空元数据目录、指标关联及字段水位，写入完整新目录。
4. 为所有字段构建语义索引，再为所有指标构建语义索引。名称、说明和别名规范化去重后直接生成向量并批量写入，不读取旧索引或比较文档差量。
5. 对启用取值索引的字段分批读取去重取值，写入索引并保存初始水位。

全量导入清理所有原有目录内容，不比较新增、修改和删除差量。配置或源表检查失败时不清理既有目录和索引。正式重建开始后 PostgreSQL 与 Elasticsearch 没有跨库原子事务，失败可能留下部分新数据，重新运行全量脚本即可从清空步骤重建。认证数据和 Doris 业务表不属于清理范围。

## 4. 字段取值增量导入

增量脚本读取数据库中的目录和水位配置，不重新载入 YAML，也不修改字段和指标的语义定义。只处理启用 `index_values` 且所属表配置了 `value_index_cursor_column` 的字段。

每张表一次读取水位最大值并固定本次上界。最大值为空、相等或小于已提交水位时跳过取值扫描并保留旧水位；推进后读取左开右闭的水位区间，分批去重、序列化并按稳定文档 ID 写入 ES。只有索引写入和刷新成功后才提交字段的新水位。

全量导入时空表的水位可以为空；以后出现首批非空水位时，从无下界开始读取至本次上界。字段尚无水位时同样从头扫描至本次上界，无需先完成全量同步。未配置水位的表明确跳过。

索引写入或刷新失败直接抛出异常，保留旧水位，不向数据库记录失败状态。重跑时可以重复写入之前已写入的部分值，稳定文档 ID 避免重复记录。重跑直接读取已提交水位，无需接管运行状态。水位字段必须随新增或更新递增；旧水位的迟到记录及源值删除需要全量重建。

字段和指标的名称、说明及别名生成全文和向量检索文档，向量维度必须与 Embedding 服务匹配。字段取值使用全文索引，不逐值生成向量。

## 5. 混合检索与上下文补全

一次 `recall_context` 可以携带 1—50 个检索词、字段/指标/取值资源类型，以及每类 1—20 个结果上限。

搜索前，系统读取当前权限和目录，生成资源白名单，加入 ES 查询条件。仅在需要检索字段或指标时统一生成一次查询向量，再分别执行字段、指标的全文与向量搜索；各通道内多个检索词并发查询，并受并发上限约束。向量生成失败时继续全文搜索。结果用倒数排名融合：看候选在各条搜索结果中的名次，而不是直接相加不同量纲的原始分数。当前 RRF 常数为 60，候选数量通常为目标上限的三倍、最多 60。

服务先加载 PostgreSQL 目录并关闭会话，再进行外部检索；命中后根据这份目录组装资源，丢弃不存在或不在当前可见集合中的键，补充指标依赖字段、已授权主键和一层外键关系。ES 旧文档仍可能影响排名；返回当前目录内容不等于已经彻底消除了旧排名影响。

有排名的直接字段及指标依赖字段最多进入 30 个上下文位置；取值所属字段、主键和外键属于补充信息，因此最终字段总数可能超过 30。发生截断会给出标志和 warning；每个返回字段最多展示 3 个示例。

Embedding 失败时，已经成功的全文结果仍可返回，并标记部分失败。字段值或某个搜索通道失败也不必吞掉其他通道的结果。`partial` 描述本次搜索的完整性。

## 6. 工具结果与消息上下文

Explorer 使用 `recall_context` 检索元数据，每次调用独立返回本次检索结果。

工具结果直接包含表、字段、指标和字段取值。字段展示类型、说明、别名、示例及关联关系；取值归入所属字段。排名和字段引入原因由召回服务计算，不维护索引运行状态。

结果正文保留在普通工具消息中，模型后续轮次直接使用。Planner Checkpoint 保存任务调用和最终返回；子 Agent 内部工具消息在本次任务中使用。

每次新检索按当前资产权限过滤。历史消息保留当次已返回的内容，不在读取时重新查询或改写；需要最新目录信息时重新召回。

## 7. 运行结果与故障定位

脚本同步执行整个流程，不以“后台任务已提交”作为成功。退出码为零表示全部步骤完成；日志记录配置校验、目录写入、语义索引构建、字段取值数量和水位。

失败时先区分 YAML/源表校验、Embedding、ES 写入和 PostgreSQL 水位提交。增量失败重新执行增量脚本；全量失败重新执行全量脚本。全量导入不会改写已有工具消息；需要新目录内容时重新召回。
