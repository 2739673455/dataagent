# 沙箱

## 1. 模块目标与边界

沙箱模块为 Agent 提供文件和命令执行环境，并封装 Docker、数据卷、会话身份、归档传输和 Redis 协调。外部业务只提交用户、会话与操作内容，不直接创建容器或维护沙箱锁。

沙箱承担计算与文件隔离，Doris 查询和语言模型调用仍由应用服务发起。网络默认关闭的容器只处理应用已交付的数据和镜像中已有的运行依赖。

## 2. 三个公共类型

对外入口只导出 DockerSandboxManager、DockerSandboxBackend 和 SandboxReadonlyMount。选择方式如下：

| 需求 | 使用对象 |
| --- | --- |
| 初始化沙箱、交付或下载文件、删除会话资源 | DockerSandboxManager |
| 给 Agent 装配文件工具、执行会话命令 | 管理器返回的 DockerSandboxBackend |
| 把宿主机技能目录提供给容器及文件工具只读访问 | SandboxReadonlyMount |

管理器由应用创建和关闭，业务服务复用它；后端绑定一个用户和会话，由管理器创建；挂载描述是构造管理器和 Agent 文件系统时使用的配置对象。业务模块不直接访问内部归档、运行池或协调器。

### 2.1 DockerSandboxManager：应用级入口

构造参数 readonly_mounts 接受只读挂载集合，默认为空。ownership 是协调器注入点，正常应用使用默认 Redis 实现，测试可替换；业务代码无需自行创建协调器。

下表除 graph_backend 外均为异步方法，调用时需要 await。user_id 为整数，conversation_id 为 UUID。

| 方法 | 参数 | 返回值与用途 |
| --- | --- | --- |
| init | start_cleanup，默认 True | 初始化客户端、运行时租约和后台清理 |
| graph_backend | user_id、conversation_id | 返回未准备执行身份的后端，用于构图及读取 Checkpoint |
| get_backend | user_id、conversation_id | 准备会话工作区和执行 UID，返回可运行后端 |
| write_artifact | user_id、conversation_id、path、content | 将二进制文件对象写入会话相对目标，返回绝对产物位置 |
| download_file | user_id、conversation_id、path | 按会话相对标识读取，返回 bytes |
| resolve_artifact | user_id、conversation_id、path | 接收绝对产物引用，返回可下载文件的相对标识；非法或不可下载时返回 None |
| delete_conversation | user_id、conversation_id | 建立删除标记并清理会话资源 |
| close | 无 | 停止后台清理、释放运行时并关闭客户端 |

write_artifact 的 content 必须是支持 seek 和 tell 的二进制文件对象，例如 BytesIO 或二进制临时文件。管理器负责定位存储位置，调用方保存返回值即可。

resolve_artifact 的 None 表示引用不可用，Docker 或 Redis 等基础设施失败仍会抛出异常。download_file 对非法目标、文件不存在和文件过大分别报告相应异常，公共业务异常由 HTTP 全局处理器直接投影。

graph_backend 不应直接用于执行命令。它没有准备会话执行身份，用于读取图状态时可以避免执行准备；真正运行 Agent 应使用 get_backend。

### 2.2 DockerSandboxBackend：会话级执行与文件后端

后端绑定用户、会话、执行 UID 和内部资源访问能力。调用方通过管理器获取，不直接调用其构造函数，也不为每次工具调用创建新的管理器。

| 属性或方法 | 输入 | 返回或作用 |
| --- | --- | --- |
| id | 无 | 后端标识 |
| workspace_dir | 无 | 当前会话工作目录，供工具装配和产物定位使用 |
| run_shell | command | 异步执行命令，返回状态、退出码、输出及日志信息 |
| execute / aexecute | command、可选 timeout | DeepAgents 命令执行协议，返回 ExecuteResponse |
| read / aread | file_path、offset=0、limit=2000 | 按行读取，返回 ReadResult |
| write / awrite | file_path、content | 创建文本文件，返回 WriteResult；已有文件由编辑操作处理 |
| edit / aedit | file_path、old_string、new_string、replace_all=False | 替换文本，返回 EditResult |
| upload_fileobj | path、二进制文件对象 | 同步上传，返回 FileUploadResponse |
| upload_files / aupload_files | 文件标识与 bytes 的二元组列表 | 批量上传，逐项返回 FileUploadResponse |
| download_files / adownload_files | 文件标识列表 | 批量下载，逐项返回 FileDownloadResponse |

带 a 前缀的方法是异步版本。Web 服务和异步工具应优先使用异步方法，避免同步 Docker 操作阻塞事件循环。文件结果对象可能通过 error 字段表达操作失败，调用方应检查结果，而不是只判断是否抛异常。

业务 shell 工具使用 run_shell，它包含任务控制文件、长输出保留和进程组取消的完整生命周期。execute 与 aexecute 主要服务 DeepAgents 后端协议和内部文件命令，不能作为 run_shell 的等价替换。

run_shell 返回的结果类型由方法提供，无需从模块入口导入。消费方通常读取 status、exit_code、output、error、output_path 及截断标记。后端本身不承担会话数据库归属检查，上层需先确认用户有权操作该会话。

### 2.3 SandboxReadonlyMount：只读挂载描述

这是不可变数据类，只有 source 和 target 两个字段，没有需要调用的业务方法。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| source | Path | 宿主机源目录；构造时严格解析为实际绝对位置，源必须存在 |
| target | PurePosixPath | 容器和 Agent 文件系统使用的只读挂载位置 |

构造时自动执行的 __post_init__ 只规范化 source。挂载由内部代码配置，目录选择和目标范围由装配方负责。

它本身不会执行 Docker 挂载，也不会创建文件路由。管理器读取它来生成容器挂载配置；Agent 文件系统装配读取相同的 source 和 target，建立文件路由与只读权限。需要技能同时能被文件工具和 shell 读取时，两处配置必须一致。

## 3. 典型使用方式

以下代码省略模块导入，变量由应用装配或服务调用提供。user_id 和 conversation_id 来自已校验的会话上下文；各文件位置使用变量表示，不由示例指定存储布局。

### 3.1 应用启动与关闭

```python
manager = DockerSandboxManager(readonly_mounts=mounts)
try:
    await manager.init()
    # 将 manager 注入查询、会话和 Agent 服务。
finally:
    await manager.close()
```

实际应用将关闭动作登记到生命周期管理器。不要在一次下载请求结束时关闭整个沙箱管理器，也不要在每个工具调用中重复构造它。

### 3.2 交付文件与解析附件

```python
absolute_reference = await manager.write_artifact(
    user_id, conversation_id, artifact_name, binary_file
)
relative_reference = await manager.resolve_artifact(
    user_id, conversation_id, absolute_reference
)
if relative_reference is not None:
    content = await manager.download_file(
        user_id, conversation_id, relative_reference
    )
```

写入和下载使用会话相对标识，模型交付引用使用 write_artifact 返回的绝对位置。resolve_artifact 负责连接这两个表示，并验证文件可下载，调用方无需再自行转换或重复检查。

### 3.3 执行命令和装配文件工具

```python
backend = await manager.get_backend(user_id, conversation_id)
result = await backend.run_shell(command)
if result.status != "completed":
    handle_failure(result.error or result.output)
else:
    consume_output(result.output, result.output_path)
```

handle_failure 和 consume_output 代表调用方自己的处理逻辑。长输出应结合 output_path 和截断标记消费，不能把内联摘要视为完整日志。

装配 Agent 时，将同一个 backend 交给文件系统中间件和 shell 工具；若文件系统使用 CompositeBackend，图使用中间件最终返回的后端。Planner 与专业 Agent 共享该会话后端，工具允许列表由 Agent 装配决定。

### 3.4 提供只读技能

```python
mount = SandboxReadonlyMount(
    source=host_skill_directory,
    target=agent_skill_directory,
)
manager = DockerSandboxManager(readonly_mounts=[mount])
```

host_skill_directory 是宿主目录 Path，agent_skill_directory 是目标 PurePosixPath。应用还需将同一个挂载描述传给 Analyst 的文件系统装配，使容器挂载和 Agent 文件路由保持一致。其他 Agent 没有技能路由时，无需添加对应装配。

### 3.5 删除会话资源

先由会话服务标记删除并取消、等待正在运行的任务，再调用 `await manager.delete_conversation(user_id, conversation_id)`。删除完成后再清理会话数据库记录；只关闭管理器不会删除该会话文件。

## 4. 用户、容器、数据卷和会话

一个应用用户对应一个容器和持久化数据卷。多个会话存放在该用户卷中，但每个会话具有独立目录和稳定 Linux UID。一个会话的 Planner 与专业 Agent 使用相同目录和执行身份。

UID 注册由受控的沙箱内部逻辑维护。工作区准备设置目录归属、权限以及命令所需的用户环境；会话命令以对应身份执行，不能仅靠“当前目录不同”实现隔离。

容器是可回收的运行资源，数据卷是文件持久化资源。空闲停止或移除容器不会删除用户卷；后续操作可重新建立运行容器并继续访问产物。

删除会话移除该会话目录并更新 UID 注册，保留用户的其他会话。管理器需要时可以准备执行删除所需的容器，不能假设所有删除都只是宿主机文件操作。

## 5. 隔离层次

| 层次         | 机制                               | 保护对象           |
| ------------ | ---------------------------------- | ------------------ |
| 应用用户     | 独立容器与数据卷                   | 不同用户的工作数据 |
| 用户内会话   | 独立 UID、归属和目录权限           | 不同会话文件       |
| 运行容器     | 只读根文件系统、网络关闭、资源限制 | 执行环境及宿主资源 |
| 业务文件入口 | 规范化、归属、文件类型和大小检查   | 下载与写入目标     |
| 技能资源     | 只读挂载                           | 静态提示和技能内容 |

容器默认移除能力并启用 no-new-privileges。受控内部操作负责准备工作区和终止进程，模型提交的命令由会话身份执行。

只读根文件系统仍允许规定的工作区和临时存储可写。容器限制、会话权限和应用校验共同构成边界；任何一层的“目标看起来正常”都不能代替其余层的检查。

## 6. 文件标识与访问规则

业务附件入口接受会话相对标识，拒绝绝对目标、父级跳转、反斜杠、控制字符和超长名称。Agent 后端支持按当前工作区解析相对引用，也识别绝对引用，但修改目标必须满足其受控范围。

resolve_artifact 要求目标确实属于当前会话，不能指向会话目录本身或隐藏资源。消息投影只调用该管理器方法，由沙箱内部完成转换和可下载检查。

只做字符串规范化不足以判断实际文件位置。文件操作还要处理符号链接、目录与普通文件类型，避免通过链接修改或下载其他会话内容。

只读挂载由代码配置，声明时解析已存在的宿主源为绝对路径；目录选择和目标范围由装配代码确定。Analyst 技能以只读方式提供给模型。

## 7. 文件传输与归档

Docker 文件传输使用归档读写。归档层负责大小检查、成员验证、工作区建立和文件属性，业务服务不直接操作 tar 条目。

上传文件及目录设置实际修改时间，文件归属由工作区准备和受控写入流程处理。产物写入成功后管理器才返回最终位置，调用方不需要自行拼接底层存储布局。

下载只返回符合要求的文件内容。不存在的容器资源或文件转换为文件不存在语义；非法目标和超大文件直接抛出公共业务异常，由全局处理器分别返回 403 与 413，并保留对应详情。

文件读取、命令执行共用 Docker 流关闭处理。连接已经断开时只忽略对应的 ENOTCONN 清理异常，仍执行响应关闭；其他错误不能一并吞掉。

## 8. 后端与命令执行

DockerSandboxBackend 实现 DeepAgents 所需的同步和异步文件方法，并提供 run_shell。异步包装将阻塞 Docker SDK 调用放到线程，不直接阻塞 Web 事件循环。

内部文件命令使用独立超时，默认 60 秒。它用于限制沙箱辅助操作，不能解释为所有用户 shell 命令统一只能运行 60 秒。

run_shell 创建唯一 job，调用 DockerShellJobRunner，获得结果后决定是否保留输出日志，最后清理控制资源。shell 工具只格式化结果，不管理进程租约或临时控制文件。

## 9. Shell 输出协议

| 字段                    | 含义                             |
| ----------------------- | -------------------------------- |
| status                  | completed、failed 或 interrupted |
| exit_code               | 能取得时返回进程退出码           |
| output                  | 可直接展示的输出摘要             |
| output_inline_truncated | 内联输出是否被截断               |
| output_truncated        | 保存的输出是否也达到限制         |
| error                   | 执行或基础设施错误说明           |
| output_path             | 保留输出文件的位置               |

内联输出上限为 80000 字节，长输出保留首尾内容并插入截断说明。输出日志也有容量限制，因此“存在输出文件”不必然代表无限完整日志，应同时看截断标记。

内联内容足够时可以清理未公开日志；需要模型继续读取长输出时保留对应文件。失败结果和退出码必须保留语义，不能把拿到一些标准输出等同于命令成功。

## 10. 取消与线程回收

取消异步等待不会自动停止执行 Docker 调用的线程，也不会自动终止容器里的进程。因此 shell 取消包含完整的外部清理过程。

1. 设置取消事件，阻止尚未开始的后续执行阶段。
2. 等待命令已启动或执行线程已经结束。
3. 对已启动 job 的进程组发送 TERM。
4. 宽限约 1 秒后必要时发送 KILL。
5. 等待执行线程退出，再向调用方传播取消。

使用进程组使子进程也能被回收。等待线程结束使租约和 Docker 流不会留在无人负责的后台状态。清理采用屏蔽取消的等待，处理取消过程中再次收到取消的情况。

上层 Run 停止后会等待这条链结束。删除会话必须在运行停止后再清理文件，避免进程继续写入已经删除或重新创建的工作区。

## 11. Redis 协调对象

| 协调对象       | 作用                               |
| -------------- | ---------------------------------- |
| 运行时租约     | 表示某个管理器实例仍在存活         |
| 操作租约       | 标记用户和会话正在进行读写或执行   |
| 容量锁         | 串行化运行容器数量检查与启动       |
| 用户结构变更锁 | 串行化容器、数据卷和工作区结构变更 |
| 会话维护窗口   | 阻止新操作并等待该会话活跃操作结束 |
| 用户维护窗口   | 等待用户操作结束后回收或维护容器   |
| 删除墓碑       | 阻止已删除会话重新被普通操作创建   |

普通操作登记租约，可以在同一线程内重入；维护操作先建立协调状态，再等待活跃操作结束。删除标记和维护状态在登记操作时共同检查，避免先检查后登记之间出现竞态。

租约定期续期，进程异常退出后到期状态可被清理。Redis 不可用或租约异常需要作为协调失败处理，不能当成“没有其他任务”而继续无保护地执行。

沙箱协调保护 Docker 资源，不能同步 Assistant 的进程内 Run 注册表和 SSE 缓冲。

## 12. 容量、空闲回收与锁顺序

运行池根据 Docker 实际状态统计运行容器。目标容器已经运行时直接复用；未达上限时启动；满载时按活动时间寻找没有操作租约的候选容器。

维护候选时先等待用户操作结束，再取得容量锁重新核对状态和容量。不能持有容量锁长期等待用户操作，否则其他操作可能无法取得启动所需容量并形成阻塞。

停止一个空闲容器后再重新检查目标容器和容量，避免依赖已经过时的列表。找不到可回收对象时报告容量已满，不强行停止活跃任务。

启动时运行池还会核对已有容器和活动记录，收敛超过限制的运行实例。周期清理按空闲时间停止或移除容器，始终保留数据卷。

## 13. 默认资源参数

| 参数                 | 默认值                   | 作用范围       |
| -------------------- | ------------------------ | -------------- |
| 镜像                 | dataagent-sandbox:latest | 容器运行环境   |
| 内存                 | 2 GiB                    | 单容器         |
| CPU 配额             | 2 核                     | 单容器         |
| 进程数               | 256                      | 单容器         |
| 最大运行容器数       | 8                        | 同一部署       |
| 单文件上限           | 50 MiB                   | 应用文件操作   |
| 用户存储检查阈值     | 1 GiB                    | 用户工作数据   |
| 空闲停止阈值         | 600 秒                   | 用户容器       |
| 空闲移除阈值         | 3600 秒                  | 用户容器       |
| 清理间隔             | 60 秒                    | 管理器后台任务 |
| 协调锁超时、等待超时 | 各 60 秒                 | Redis 协调     |
| 运行时和操作租约     | 30 秒                    | Redis 存活判定 |

这些参数是模块常量。默认 local 数据卷驱动没有硬配额，应用检查阈值不能保证任意 shell 写入都被限制在相同容量内，需要同时关注宿主机磁盘和可用的存储驱动能力。

## 14. 初始化、关闭和部署

初始化需要连通 Docker 和 Redis，建立资源命名空间与运行时租约，再启动空闲清理。初始化放在线程中的部分被取消时，也要等待线程完成并回收它已经创建的资源。

关闭时停止清理任务和续租，释放当前运行时，再按是否仍有其他活跃运行时决定容器收尾，最后关闭客户端。默认启用退出时停止容器，数据卷继续保留。

同一 Docker 主机的独立部署应使用不同部署命名空间。镜像提供 Python、Node、字体及分析依赖，新增依赖要修改构建输入并重建镜像；禁网容器不能临时从外网补装包。
