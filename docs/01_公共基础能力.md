# 01. Shared：公共基础设施与运行机制

Shared 提供配置校验、外部客户端、跨模块契约、错误协议、日志追踪和 Celery 任务设施。业务模块使用这些能力完成自己的用例，连接与任务基础设施不保存具体业务规则。

## 1. 提供哪些功能

```text
Shared：公共基础能力
├── 配置加载（Web、Worker、Beat、CLI）
│   ├── 加载进程环境变量与 conf/.env
│   ├── 读取 YAML 并解析环境变量引用
│   ├── 校验配置字段、资源限制和模型引用
│   └── 提供类型化的配置对象与秘密值字段
├── PostgreSQL 访问（业务仓储、应用入口）
│   ├── 创建数据库引擎和连接池
│   ├── 提供异步会话工厂，供业务代码建立读写事务
│   ├── 按指定业务模型注册表创建缺失的数据表
│   └── 关闭连接池并释放数据库资源
├── Doris 连接管理（Identity、Metadata、Query）
│   ├── 提供源结构读取与角色权限管理连接
│   ├── 按角色和查询凭据创建或复用查询连接池
│   ├── 凭据变化时替换旧查询连接池
│   └── 失效指定角色连接池或关闭全部查询池
├── 向量服务（索引与检索服务）
│   ├── 向远程 Embedding 接口提交一批文本
│   ├── 按输入顺序返回向量并检查响应数量
│   └── 按配置设置鉴权和超时，释放 HTTP 客户端
├── 业务互斥（会话执行、生命周期操作）
│   ├── 按稳定业务键获取跨进程 PostgreSQL 锁
│   ├── 检测同进程重复持锁并报告锁忙
│   └── 操作退出时解锁并归还专用连接
├── 公共契约（跨模块调用）
│   ├── 生成数据源、数据库、表和列的稳定资产键
│   ├── 统一分析标识格式、专家类型与 Doris 工作组名称规则
│   ├── 提供搜索命中对象与得分结构
│   └── 提供任务提交结果与任务状态响应结构
├── 错误与日志（HTTP、工具、任务入口）
│   ├── 定义业务异常和 Problem Details 响应
│   ├── 统一处理参数、业务、HTTP 和未处理异常
│   ├── 返回参数错误明细和限流重试提示
│   ├── 绑定并返回请求标识与链路标识
│   ├── 维护请求和用户日志上下文，结束时恢复
│   └── 输出控制台日志与轮转 JSONL 日志
└── 任务与异步运行（Worker、Beat、CLI）
    ├── 配置 Celery Broker、结果存储和任务路由
    ├── 配置任务时限、预取和消息重投
    ├── 安排索引、会话清理和用户注销等周期任务
    ├── 提供后台任务执行状态协议
    ├── 在同步入口创建事件循环并返回协程结果
    └── 为 Windows 数据库客户端选择兼容的事件循环
```

## 2. 如何使用

### 2.1 读取和修改配置

Web、Worker、Beat 和 CLI 共用 `cfg`。服务启动前准备 `conf/app_config.yaml`，其中的秘密值引用由进程环境变量或 `conf/.env` 提供。

```python
from app.shared.config.app_config import cfg

batch_size = cfg.embedding.batch_size
query_timeout = cfg.query.timeout_seconds
```

| 操作 | 输入与结果 |
| --- | --- |
| 首次导入配置模块 | 加载环境变量和 YAML，返回经过 Pydantic 校验的 `Cfg` 实例 |
| 读取配置 | 通过 `cfg.<配置组>.<字段>` 取得类型化的值 |
| 修改运行参数 | 修改 YAML 或相应环境变量，然后重启使用该配置的进程 |
| 排查配置错误 | 查看缺失的环境变量、字段路径和校验原因，修正后重新启动 |

配置在模块导入阶段加载。导入成功只表示配置结构和取值通过检查，数据库、Redis、模型等外部服务是否可用，还需在连接或实际调用时确认。

### 2.2 取得服务所需资源

通常由应用入口创建客户端，业务服务通过构造参数接收所需实例。Web 资源位于 `app.state.resources`，HTTP 依赖从中选取对象。

| 运行场景 | 谁创建资源 | 谁关闭资源 |
| --- | --- | --- |
| Web 请求 | `app/runtime.py` 创建进程共享客户端，HTTP 依赖创建请求服务 | 应用退出关闭客户端，请求上下文关闭会话 |
| Celery 任务 | 任务的资源上下文 | 任务完成、失败或取消时释放 |
| 独立脚本 | 脚本异步入口 | 同一入口的 `finally` 或上下文管理器 |
| 普通业务方法 | 使用已注入的客户端，按需创建短会话 | 方法关闭自己的会话，客户端由创建方关闭 |

一个业务方法使用哪些客户端，就接收哪些依赖。连接池绑定创建它的进程和事件循环，不能跨独立任务的事件循环直接复用。

### 2.3 访问 PostgreSQL

`PostgresClientManager` 接收 `DBConfig`，提供 SQLAlchemy 异步会话工厂。适用于业务仓储读写，以及启动时创建指定模型的数据表。

| 方法 | 输入 | 返回或效果 |
| --- | --- | --- |
| `PostgresClientManager(config)` | 对应数据库配置 | 创建引擎和会话工厂，连接按需建立 |
| `session()` | 无 | 返回 `AsyncSession`，通过异步上下文管理生命周期 |
| `init_tables(metadata)` | 业务模块的 SQLAlchemy `MetaData` | 创建尚不存在的数据表 |
| `close()` | 无 | 释放连接池 |

以下示例在异步脚本中创建资源；Web 业务服务可直接使用注入的 `postgres`：

```python
from sqlalchemy import text

from app.shared.clients.postgres_client_manager import PostgresClientManager
from app.shared.config.app_config import cfg

postgres = PostgresClientManager(cfg.meta_postgresql)
try:
    async with postgres.session() as session:
        value = await session.scalar(text("SELECT 1"))
finally:
    await postgres.close()
```

业务写入使用显式事务：

```python
async with postgres.session() as session, session.begin():
    session.add(entity)
```

第二个片段用于服务方法，`postgres` 为仍在使用中的注入实例，`entity` 为所属模块已构造的 ORM 对象。

| 结束情况 | 会话与事务行为 |
| --- | --- |
| `session.begin()` 正常退出 | 提交事务 |
| 事务内抛出异常 | 回滚事务，异常继续交给调用方 |
| 仅退出 `session()` 上下文 | 关闭会话，不自动提交业务修改 |
| 已提交后，外部任务投递失败 | 数据仍已保存，调用方按业务规则补投或恢复 |

数据库连接、约束或执行错误会向上传播，由业务模块决定错误映射。建表使用所属模块的注册表，`init_tables()` 不负责已有表结构迁移。

### 2.4 访问 Doris

管理连接和用户查询连接使用不同入口：

| 入口 | 适用场景 | 身份来源 |
| --- | --- | --- |
| `DorisClientManager(cfg.doris)` | 读取源结构，管理角色与授权 | 部署配置中的管理账号 |
| `DorisQueryClientRegistry` | 为受控 SQL 执行取得查询连接池 | Identity 解析出的角色、查询用户名和密码 |

已注入的管理客户端可按以下方式读取连接：

```python
from sqlalchemy import text

async with doris.engine.connect() as connection:
    result = await connection.execute(text("SELECT 1"))
    value = result.scalar_one()
```

查询连接池注册表的操作：

| 方法 | 参数 | 结果与归属 |
| --- | --- | --- |
| `get_or_create(role_name, query_user, password)` | 当前解析出的查询身份 | 返回该身份对应的 `DorisClientManager`；用户名或密码变化时替换旧池 |
| `invalidate(role_name)` | 角色名 | 移除并关闭该角色连接池 |
| `close()` | 无 | 关闭注册表持有的全部查询池 |

注册表使用配置中的数据库端点，使用调用方传入的查询凭据建连。业务 SQL 经 Query 服务设置工作组、超时和内存限制后执行；取得连接池本身不会执行这些业务检查。

连接上下文归调用方法管理，连接池归应用或任务资源上下文管理。连接或权限错误需要结合 Doris 返回原因和当前查询身份排查。

### 2.5 生成文本向量

`EmbeddingClient` 接收 `EmbeddingConfig`，调用配置端点的 `/embeddings`。索引服务为文档生成向量，检索服务为查询词生成向量。

异步脚本中的完整资源示例：

```python
from app.shared.clients.embedding_client import EmbeddingClient
from app.shared.config.app_config import cfg

embedding = EmbeddingClient(cfg.embedding)
try:
    vectors = await embedding.aembed_documents(["销售收入", "订单日期"])
finally:
    await embedding.close()
```

| 情况 | 返回或行为 |
| --- | --- |
| 输入非空字符串列表 | 返回 `list[list[float]]`，按响应索引恢复为输入顺序 |
| 输入空列表 | 返回空列表，不发 HTTP 请求 |
| 响应缺少 `data` 列表 | 抛出 `TypeError` |
| 响应向量数量与输入不同 | 抛出 `ValueError` |
| HTTP 状态失败、超时或响应无法解析 | 异常向上传播，由业务服务处理 |

客户端每次调用发送一批输入；索引服务根据 `cfg.embedding.batch_size` 切分批次。向量维度需与 ES 映射一致，调用方负责选择重试、报告索引失败或在检索时保留可用通道。

### 2.6 保护跨进程互斥操作

`PostgresAdvisoryLocks` 用于保护同一会话或业务键的操作。所有竞争方需使用相同数据库和锁名；同一进程内也检查重复持锁。

```python
from app.shared.clients.postgres_advisory_locks import PostgresAdvisoryLocks
from app.shared.config.app_config import cfg

locks = PostgresAdvisoryLocks(cfg.langgraph_postgresql)
try:
    await locks.init()
    async with locks.advisory_lock(lock_name):
        await protected_operation()
finally:
    await locks.close()
```

示例中的 `lock_name` 是业务层生成的稳定键，`protected_operation()` 是待保护的异步操作。已注入的锁服务只需使用 `advisory_lock()` 上下文。

| 情况 | 行为 |
| --- | --- |
| 成功取得锁 | 进入上下文，持有专用数据库连接直至操作退出 |
| 同名锁已被占用 | 抛出 `AdvisoryLockBusyError`，调用方决定返回忙碌或稍后重试 |
| 操作结束或抛出异常 | 执行解锁并归还连接；异常继续传播 |
| 连接池或数据库不可用 | 连接错误向上传播 |

非阻塞指锁竞争时不等待占用者完成，取得连接仍受连接池可用性影响。锁只控制互斥，任务进度、结果和跨进程事件由业务模块管理。

### 2.7 使用后台任务与同步脚本

在项目根目录的独立终端中启动进程：

```bash
uv run celery --app app.shared.tasks.celery_app:celery_app worker -l INFO
uv run celery --app app.shared.tasks.celery_app:celery_app beat -l INFO
```

Worker 消费任务，Beat 发出定时任务。业务调用通过所属模块的调度器提交，典型返回类型为 `TaskSubmission`，其中 `task_id` 表示已提交的 Celery 任务；具体调度器以自身返回契约为准。

1. 完成当前业务事务。
2. 调用模块任务调度器，保存或返回任务标识。
3. 管理员通过 `GET /api/v1/tasks/{task_id}` 查询执行结果。
4. 结合业务数据库中的状态或版本确认最终效果。

任务状态响应：

| 字段 | 含义 |
| --- | --- |
| `task_id` | 查询的任务标识 |
| `state` | Celery 当前状态 |
| `ready` | 任务是否进入终态 |
| `successful` | 成功与否；未结束时为 null |
| `result` | 成功任务的返回值 |
| `error` | 失败任务的错误信息 |

PENDING 也可能来自未知任务或已过期结果。Broker 投递失败、任务执行失败和业务尚未完成分别处理，调度器不会自动回滚调用前已经提交的事务。

同步 CLI 或 Celery 函数使用 `run_async()` 进入异步逻辑：

```python
from app.shared.async_runtime import run_async

async def main():
    # 在这里创建、使用并关闭本次执行需要的异步资源。
    return "finished"

result = run_async(main())
```

`run_async()` 返回协程结果，异常继续抛出。已处于异步函数内时直接 `await`；独立调用创建独立事件循环，资源在该次调用结束前释放。

### 2.8 定义业务错误与定位请求

业务异常放在所属模块的 `errors.py`，继承 `ProblemError`，由应用入口注册的全局处理器生成 HTTP 响应。新增用例通常抛出模块异常即可。

```python
from app.shared.errors.base import ProblemError

class ExampleResourceBusyError(ProblemError):
    type = "example-resource-busy"
    title = "资源正在使用"
    status = 409
```

上例展示新增异常的定义方式，实际类型名和状态由所属业务模块确定。

| 响应字段 | 用途 |
| --- | --- |
| `type` | 错误分类，供客户端分支处理 |
| `title` | 简短说明 |
| `status` | HTTP 状态码 |
| `detail` | 可选的具体原因 |
| `instance` | 发生错误的请求路径 |
| 扩展字段 | 如参数错误列表 `errors`，或限流等待时间 |

请求校验错误返回 422；未处理异常返回通用 500，完整异常保留在日志中。工具调用和已开始的 SSE 使用各自的错误协议。

定位请求时：

1. 记录响应头 `X-Request-ID` 和 `X-Trace-ID`。
2. 按标识检索控制台或 JSONL 日志。
3. 若后续提交了任务，再按任务 ID、用户、Conversation 或资源键关联后台日志。

中间件接收已有请求标识，缺少时生成 UUID；Trace ID 缺少时使用 Request ID。请求结束恢复日志上下文。日志中的转发 IP 用于观察，认证限流使用 ASGI 连接来源并依赖可信代理配置。

## 3. 关键使用规则

### 3.1 资源生命周期

Web 进程在 `app/runtime.py` 内创建一份 `WebResources`，挂到 `app.state.resources`。API dependencies 从中选择需要的服务，不把整个资源容器传进业务服务。

资源创建与释放顺序：

1. 构造一个资源。
2. 立即向 `AsyncExitStack` 登记该资源的关闭动作。
3. 继续构造和初始化后续资源。
4. 正常退出、初始化失败或任务取消时，逆序执行已登记的关闭动作。

一个组件关闭失败后，其余关闭动作仍会尝试执行；外部清理仍可能失败，需要保留错误日志。

数据库引擎、会话工厂和 Embedding/ES 客户端在构造时创建；需要异步初始化的包括 Checkpoint 连接池与表、业务锁连接池、沙箱、四个业务模型注册表的表和 Agent 管理器。运行时工厂中的模型和工具资源按其生命周期创建、复用和关闭。

Celery 任务使用任务自己的资源作用域。不要把上一次 `asyncio.run()` 中创建的异步客户端留到下一个事件循环继续使用；即使“又创建了一个模型对象”，它也可能共享底层 HTTP 客户端。项目的模型工厂明确管理同步和异步 HTTP 客户端，标题任务等入口在对应作用域退出前关闭它们。

### 3.2 会话、事务和状态

| 机制 | 维护的状态 | 不承担的职责 |
| --- | --- | --- |
| SQLAlchemy Session | 当前数据库访问上下文 | 进入上下文不自动提交业务修改 |
| 数据库事务 | 同一数据库内的一组变更 | 不覆盖 ES、Doris、Docker 或 Broker |
| Advisory Lock | 特定会话或业务键的互斥 | 不持久化任务进度、不转发事件 |
| Celery AsyncResult | 有期限的任务执行结果 | 不替代索引版本或注销任务状态 |
| ContextVar | 当前请求/任务的日志关联 | 不替代用户和会话归属检查 |

连接池属于创建它的进程和事件循环。短会话用于普通读写；有明确互斥用途的锁连接可以覆盖长操作。初始化、业务提交、消息投递和资源关闭分别处理错误，调用方根据已完成阶段决定补偿或重试。

### 3.3 公共契约归属

Shared 中的 contracts 保存跨模块共同使用的标识和数据结构，避免各处自行拼接用户、会话、表和字段名称。

| 契约 | 所属模块 | 内容与用途 |
| --- | --- | --- |
| 分析标识与专家类型词汇 | Shared | 统一分析标识格式和配置中的专家类型 |
| `AgentSessionKey` | Assistant `models/session.py` | 用户、Conversation、Analysis、专家类型和 Session 标识；由 `sessions/identity.py` 转换为 Checkpoint namespace |
| `QueryExecutionScope` | Query | 查询审计和产物归属信息 |

专业 Session 的目录身份来自服务端上下文。

资产键区分数据源、数据库、表和列。名称及组合键使用统一规范，避免简单字符串拼接造成歧义。共享搜索契约 `SearchHit` 保存命中对象和得分；索引状态、截断及部分失败等业务结果由对应模块的契约定义。跨模块通过这些数据结构交换结果。

## 4. 内部实现

### 4.1 目录职责

```text
shared/
├── config/          配置模型与加载
├── clients/         数据库、向量客户端及业务锁
├── contracts/       通用标识、资产键和搜索命中
├── errors/          Problem Details 与异常处理
├── observability/   日志、请求与链路上下文
├── tasks/           Celery 配置、任务状态和提交结果
└── async_runtime.py 同步入口的事件循环
```

共享实现依赖通用库和 Shared 自身；业务模型、权限和清理顺序由各业务模块维护。模块边界测试检查导入方向和 ORM 注册表归属。

### 4.2 配置加载

配置加载顺序：

1. 加载 `conf/.env` 中的环境变量。
2. 通过 OmegaConf 解析 `conf/app_config.yaml` 中的引用。
3. 交给 Pydantic 校验，拒绝未知字段并检查端口、超时和并发上限等取值。

这一步发生在模块导入阶段。因此，缺失环境变量或配置拼写错误可能在 HTTP 服务启动前、甚至执行脚本或加载 Celery 时就报错。修改配置后，需要重启相关 API、Worker 或 Beat 进程；配置不是每次请求都从磁盘重新读取。

环境变量用于密码、令牌签名密钥和模型 API Key。YAML 描述服务地址、模型选择、资源限制及调度策略。`SecretStr` 减少对象打印时暴露秘密的机会，但不能代替日志审查；代码显式取出秘密后仍应谨慎处理。

| 配置组                                                       | 管什么                                        |
| ------------------------------------------------------------ | --------------------------------------------- |
| `auth_postgresql` | 认证数据库连接 |
| `meta_postgresql` | 元数据与查询数据库连接 |

### 4.3 数据库与外部客户端

#### PostgreSQL 会话与事务

`PostgresClientManager` 构造函数只接收连接配置，在构造时创建 SQLAlchemy 异步引擎 `engine` 和会话工厂 `session`，驱动是 `postgresql+psycopg`。默认连接池基础容量 10，允许额外 20 条连接，启用连接健康检查和定期回收。

直接调用会话工厂 `session()` 返回一个数据库会话；无需另行调用初始化或获取客户端的接口。进入 `async with session` 主要负责关闭资源；需要提交的业务操作必须明确建立事务。仓储表达 SQL 和行锁，服务或状态存储决定事务范围。

查询身份、元数据校验和查询记录分别使用短会话，Doris 执行期间不会继续占着前两阶段的 PostgreSQL 事务。有明确跨进程互斥职责的锁连接或锁事务则会覆盖相应操作，这属于有意持有，不应与漏关事务混为一谈。

业务 ORM 基类分别位于 Identity、Metadata、Query、Assistant 的 `models/base.py`。Web 启动或管理员引导脚本调用 `init_tables(metadata)`，明确传入需要建表的注册表元数据；后台任务只需创建连接管理器。共享数据库客户端不持有业务注册表，Metadata 与 Query 即使共用物理数据库也保持独立模型和会话。

#### Doris 管理连接与查询连接

`DorisClientManager` 使用 `mysql+asyncmy`，构造时创建引擎，通过 `engine.connect()` 获取连接。管理连接读取源结构、维护角色权限；`DorisQueryClientRegistry` 按角色管理查询账号的连接池，并根据用户名和密码指纹判断能否复用。凭据变化会替换旧池。

用户查业务数据使用角色对应的查询身份。配置里的后台管理账号不应成为所有用户查询的通用身份。

#### LangGraph 持久化与执行锁

`PostgresCheckpointStore` 位于 Assistant 的 `repositories/checkpoint.py`，持有 Checkpoint 连接池和原生 `AsyncPostgresSaver`。图装配、状态读取和线程删除直接使用 Saver；Store 只补充 namespace 列举、原子清理和用户线程筛选等业务操作。

`PostgresAdvisoryLocks` 独立管理业务锁连接池，将锁名稳定映射为 bigint，并检查同进程内的锁重入。Checkpoint 池最多 20 条连接，锁池最多 12 条，与 SQLAlchemy 会话池各自独立。Web 和清理 Worker 分别登记资源释放，先停止执行任务及 Agent，再关闭锁池和 Checkpoint 池；初始化失败或取消也按此顺序清理。

会话执行锁使用专用数据库连接，防止两个进程同时修改同一份图状态。锁可以阻止第二次执行，却不会把 SSE 消息转发到另一个 API 进程，也不会替其他进程取消任务。

#### HTTP 与搜索客户端

| 客户端 | 实现与职责 |
| --- | --- |
| `EmbeddingClient` | 持有 HTTP 客户端，调用 OpenAI 兼容向量接口；按配置设置鉴权和超时，检查响应数量并按索引恢复顺序 |
| `AsyncElasticsearch` | 使用原生异步客户端访问搜索索引 |

使用规则：

- Web、Worker 和 CLI 在各自的资源作用域内创建、使用和关闭客户端。
- 配置和索引使用方保证向量维度与 ES 映射一致，客户端保持接口返回的输出维度。
- 服务层负责业务级部分失败处理和重试。

### 4.4 事件循环

CLI 和 Celery 的同步函数通过 `app/shared/async_runtime.py` 启动一次独立事件循环。Windows 下显式使用 SelectorEventLoop，以兼容 Psycopg 的异步连接；`main.py` 的 Uvicorn 启动也使用对应循环工厂。

这项适配解决的是 Python 客户端循环类型，和 PostgreSQL 是否运行在 Docker 中无关。这项循环适配不代表整个服务具备原生 Windows 全栈兼容性。

### 4.5 错误与追踪

| 入口 | 错误展示方式 |
| --- | --- |
| 普通 HTTP 请求 | `application/problem+json`，包含类型、标题、状态、详情和请求定位信息 |
| 工具调用 | 工具协议中的错误载荷 |
| 已开始的 SSE 流 | `error` 事件；HTTP 响应开始后无法改发 Problem Details |

参数校验、已知业务错误、HTTP 异常和未处理异常分别进入全局处理器。

前端基于这些字段展示可理解的提示。完整数据库堆栈应留在日志中；接口的结构化错误用于说明用户能采取的下一步。

HTTP 中间件设置请求与链路跟踪上下文，返回相关跟踪头；请求结束后恢复 `ContextVar`，防止并发请求混用上一次的标识。日志同时支持控制台输出和按配置轮转的 JSONL 文件。

排查时先定位一次请求，再沿 Conversation、任务 ID、资源键或用户 ID 找到后台操作。一个 HTTP 请求结束后发出的 Celery 任务有自己的执行生命周期，不应仅凭时间相邻就认定两条日志属于同一项工作。

跨域由 `cors_origins` 白名单控制。前端开发代理和后端 CORS 是两个概念：同源代理可以避免浏览器直接跨域，但不会修改后端认证和权限规则。

### 4.6 任务队列与调度

Celery Worker 消费任务，Beat 定时发出任务。任务队列的结果存储保留默认一天，业务是否已同步、已删除，则应查看 PostgreSQL 中的状态和版本。Broker 使用迟确认及 Worker 丢失后的重投策略，仍然可能重复投递，任务必须按各自业务规则处理幂等。

| 队列             | 当前主要用途                             |
| ---------------- | ---------------------------------------- |
| `default`        | 未专门指定路由的任务                     |
| `metadata-index` | 元数据索引、取值同步、查询经验索引与修复 |
| `lifecycle`      | 会话资源清理、用户注销及相关补偿调度     |
| `lightweight`    | 会话标题生成                             |

| 执行参数 | 当前默认值 |
| --- | --- |
| 单任务软时限 | 3300 秒 |
| 单任务硬时限 | 3600 秒 |
| 预取倍数 | 1 |
| Redis 消息可见性时限 | 硬时限加 300 秒 |

业务重试等待时间由各任务自己的规则决定。

| 定时工作             | 当前默认频率              | 说明                                           |
| -------------------- | ------------------------- | ---------------------------------------------- |
| 字段值索引调度       | 每日 08:00，Asia/Shanghai | 按同步状态和游标能力安排任务                   |
| 草稿与待删除会话清理 | 每 300 秒                 | 草稿默认保留 1440 分钟                         |
| 用户注销补偿         | 每 300 秒                 | 首次受理立即投递，这里处理漏投、失败和过期租约 |
| 查询经验索引修复     | 每 300 秒                 | 找回状态或索引版本未完成同步的记录             |

不同任务的重试策略不同。用户注销的业务重试由数据库调度，未启用 Celery 自动重试。

## 5. 异常与排障

| 现象 | 检查内容 |
| --- | --- |
| 服务或脚本导入即失败 | `conf/.env`、环境变量引用、YAML 字段及配置校验错误 |
| 数据库连接耗尽 | 会话关闭、事务范围、运行并发和连接池等待 |
| 跨事件循环连接错误 | 客户端是否跨多次 `run_async()` 复用 |
| 向量请求或索引写入失败 | 服务凭据、响应数量、超时、模型输出维度与 ES 映射 |
| 任务长期 PENDING | Worker、队列路由、Broker；未知任务也可能返回 PENDING |
| 任务执行完但业务未完成 | 业务数据库中的状态、版本和任务日志 |
| 请求日志难以关联 | 请求标识、Conversation、用户、任务 ID 及 ContextVar 清理 |

修改配置后重启使用它的进程。排查异步任务时，以任务 ID 和业务状态关联日志；HTTP 请求成功只说明该请求对应阶段已经完成。
