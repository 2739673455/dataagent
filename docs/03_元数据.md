# 元数据

## 1. 模块职责

元数据模块解决模型如何找到业务数据的问题。它把人工维护的业务描述、Doris 中的真实结构和字段取值整理为目录与索引，再根据用户权限返回可用于编写 SQL 的上下文。

模块包含两个主要用例：MetaIndexService 执行全量导入和取值增量同步；SemanticRecallHandler 组织授权读取、目录加载和语义召回。导入使用管理连接，在线召回使用当前用户的资产策略过滤结果。

## 2. 配置与目录模型

| 对象         | 主要内容                                     | 来源                   |
| ------------ | -------------------------------------------- | ---------------------- |
| TableConfig  | 名称、事实或维度角色、说明、水位列、字段集合 | YAML                   |
| ColumnConfig | 名称、说明、别名、取值索引开关、引用字段     | YAML                   |
| MetricConfig | 名称、说明、别名、依赖字段                   | YAML                   |
| TableInfo    | 表描述、角色、主键、水位列                   | YAML 与 Doris          |
| ColumnInfo   | 字段类型、说明、样例、别名、引用和取值水位   | YAML、Doris 与同步结果 |
| MetricInfo   | 指标说明、别名、关联字段                     | YAML                   |
| ColumnMetric | 指标与字段的关联关系                         | 指标配置               |
| ValueInfo    | 表、字段和取值文本                           | Doris 数据             |

字段通过表名和字段名组成的联合键区分，指标通过名称区分。字段引用也使用表和字段组合，避免把不同表的同名字段混在一起。

目录保存的是业务结构，ES 文档保存的是检索表示。一个字段的名称、说明、多个别名可以对应多条 ES 文档，但召回时仍合并为同一个字段。

## 3. 配置校验与源表检查

parse_metadata_yaml 负责 UTF-8 解码、安全 YAML 解析、Pydantic 结构校验和配置内部引用检查。

结构校验限制名称、别名和描述，拒绝未知字段，并要求外键引用的表名和字段名同时给出。内部校验要求表名、指标名及表内字段名唯一，外键引用和指标依赖必须指向配置中的字段。

MetaIndexService 随后访问 Doris，确认源表、配置字段和水位列存在，读取真实字段类型、主键和样例。全部目录对象准备完成后才开始重建索引，源表错误不会等到向量生成阶段才暴露。

配置允许空表集合及无依赖字段的指标。导入调用方应理解这些输入的业务含义；无依赖指标在召回时要求整库访问权限。

## 4. 全量导入的顺序

入口为 `make import-full`，完整流程如下：

1. 解析配置并取得导入互斥锁。
2. 校验 Doris 结构，构造完整表、字段和指标对象。
3. 依次重建字段、指标和字段取值索引。
4. 在一个 PostgreSQL 事务内替换目录与取值水位。
5. 为字段构建文本和向量文档，批量写入并刷新。
6. 为指标执行同样的语义索引构建。
7. 扫描启用取值索引的字段，完成文档写入及水位保存。

目录替换先清理关联和实体，再写表。字段之间可能互相引用，因此暂存引用信息，先插入全部字段，再恢复引用，最后写入指标及指标字段关联。这一过程在同一目录事务内完成。

ES 重建与目录事务不具备原子切换。导入期间在线检索可能看到空索引或不完整结果；导入中途失败后，应修复原因再完整重跑。

## 5. 语义文档构建

字段和指标共用文档构建流程，区别在资源键与 payload。每个资源依次提供名称、说明和别名，文本经过 NFC 规范化、首尾去空及空字符串过滤。

同一资源内相同文本只保留一次，文本类型按名称、说明、别名的先后顺序确定。不同资源即使有相同文本也保留各自文档，因为资源归属不同。

资源文本排序后跨资源汇总，每批 64 条请求向量服务。向量与原始文本严格一一对应；文档 ID 由资源类型、资源键和规范化文本生成确定性的 UUID5。

每条文档包含资源键、文本、文本类型、向量和资源 payload。SemanticIndexRepo 负责公共的映射、批量写入和检索，字段与指标仓储提供自己的资源过滤条件及 payload 类型。

当前过程先构造一类资源的全部语义文档，再按默认每批 100 条写入 ES，结束后刷新。外部向量请求次数近似为文本总数除以 64 向上取整，内存需求则随该类文档和向量总量增长。

## 6. 取值索引与水位

字段取值采用全文索引，不做向量生成。取值转换为文本，日期时间使用 ISO 表示，空值跳过。文档使用稳定键，重复写入会覆盖对应文档，因此重跑同一窗口不会不断累积重复文档。

水位配置在表上，已处理水位保存在字段上。一张表的多个字段可以有不同完成进度，但同一轮读取该表最大水位时使用缓存，保证这一轮共享上界。

水位以包含 type 和 value 的 JSON 保存，支持日期、时间、Decimal 和基本标量。反序列化恢复原始类型后再交给 Doris 条件比较，避免把数值或日期一律按字符串比较。

## 7. 增量同步流程

入口为 `make import-incremental`。增量读取已导入目录，不重新解析配置。目录为空时要求先全量导入；没有配置水位列的表直接跳过。

对一个启用取值索引的字段：

1. 短事务读取字段、表配置和旧水位。
2. 取得本轮最大水位。
3. 最大水位为空或未推进时跳过。
4. 存在旧水位时扫描左开右闭区间；没有旧水位时从头扫描到本轮上界。
5. 分批覆盖写入取值文档，有写入时刷新索引。
6. 成功后用新事务保存上界。

即使某个窗口没有可索引的非空取值，只要扫描成功，也可以推进已处理水位。日志中的写入数量包含覆盖已有文档，不等于新增唯一取值数量。

全量取值扫描读取全部取值，并为配置了水位列的表记录本轮上界。它不会用该上界限制全量扫描，因此并发到达的数据可能被提前收录；后续增量允许再次覆盖这些文档。

## 8. 失败、重跑与互斥

| 失败阶段                 | 已发生的变化               | 重跑语义                 |
| ------------------------ | -------------------------- | ------------------------ |
| 配置或源表校验           | 尚未重建目录和索引         | 修正配置后全量执行       |
| 目录替换之后的向量生成   | 目录已更新、索引可能不完整 | 全量重跑                 |
| 字段取值写入中途         | 部分 ES 文档可能已写入     | 旧水位保留，窗口重新扫描 |
| ES 成功、水位提交失败    | ES 已有本轮文档            | 再次覆盖写入后提交水位   |
| 某字段成功、后续字段失败 | 前面字段水位已推进         | 增量重跑按字段继续       |

全量与增量共用 Redis 租约锁，锁范围由元数据数据库连接标识确定。抢锁不等待，已有任务运行时直接失败。租约为 60 秒，每 20 秒续租；续租失败通过任务组取消正在进行的导入，释放时按持有者 token 校验。

增量要求源数据更新能推进水位。迟到数据使用相同或更旧水位、源记录删除、取值从旧值改为新值，都不能依靠取值追加索引完整反映当前集合；需要全量重建清除陈旧取值。

## 9. 召回前的授权目录

SemanticRecallHandler 读取本次用户策略和元数据目录，在读取会话之外执行外部检索。SemanticResourceRecallService 创建只包含授权资源的 SemanticCatalog。

过滤规则包括：

- 字段必须具备完整 SELECT 权限。
- 表可因某个下级字段可读而可见，但主键名称只保留授权部分。
- 指向未授权字段的外键引用从返回副本中移除。
- 指标依赖字段必须全部授权；没有依赖字段的指标要求整库权限。

过滤构造新的目录对象，不修改共享持久化实体。上下文补充只能从这个过滤后的目录取数据，因此补主键和外键不会重新带出无权限字段。

## 10. 检索执行和排名融合

请求最多包含 50 个检索词，资源类型可选择字段、指标或取值，每类返回上限默认 5、最大 20。索引层扩召数量为该上限的三倍。

字段和指标共享一次查询向量生成，各自依次执行全文和向量通道。每个通道对多个检索词并发请求，当前服务实例最多同时执行 8 个索引查询。取值仅执行全文查询，但会融合多个词的命中。

每个检索结果按原始排名贡献 `1 / (60 + rank)`。字段和指标在单词单通道内按资源去重，避免同一资源的多个别名文档重复计分。不同词、不同通道的贡献可以累加。

三类资源分别排序、截断和按本类最高分归一化，同分按资源键稳定排序。rank_score 是相对排序分数，不是正确概率，也不适合直接跨资源类型比较。

## 11. 字段上下文组装

ColumnContextBuilder 按顺序加入直接召回字段、指标依赖字段和命中取值所属字段，再从参与表补充直接外键及引用目标，最后为最终参与表补充主键。

外键补充先固定当时的参与表集合，遍历这些表中的可见外键；新加入的引用表不会继续递归展开外键，但会参与后续主键补充。

| inclusion_reasons | 含义             | 是否占用 30 个基础名额 |
| ----------------- | ---------------- | ---------------------- |
| direct_match      | 字段自身召回     | 是                     |
| metric_dependency | 指标依赖字段     | 是                     |
| value_owner       | 命中取值所属字段 | 否                     |
| foreign_key       | 参与表的外键字段 | 否                     |
| reference_target  | 外键直接引用目标 | 否                     |
| primary_key       | 参与表主键       | 否                     |

相同字段只返回一个对象，原因列表合并。例如字段同时直接命中和作为指标依赖出现，会包含两种原因；只有直接召回带来字段排名分数。补充字段不占基础名额，因此最终数量可能超过 30。每个字段最多返回 3 个样例。

## 12. 结果投影与失败信息

内部召回响应包含 tables、columns、metrics、values，以及 status、failures、warnings、truncated。向量生成失败时继续全文检索；某个词的索引请求失败单独记录，不直接丢弃其他成功通道。

status 为 partial 表示出现后端失败；truncated 表示候选或基础字段上下文被截断。空结果本身不等于后端失败，不能将二者混为一谈。

Agent 工具对内部结果再次投影：按表组织字段，把命中取值放入所属字段，并返回指标说明和依赖。当前工具只返回 tables 和 metrics，不传递内部排名、引入原因或部分失败元信息。维护调用方时必须区分服务响应与模型实际收到的对象。
