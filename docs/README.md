# DataAgent 从零实现讲义

这套讲义从空的 `app/` 目录开始，逐步实现 DataAgent 后端。章节按代码依赖方向排列，每完成一章，项目都会增加一组可运行、可测试的能力；全部章节完成后，代码将与仓库当前版本的完整后端对应。

## 开始前需要掌握什么

开始学习前，需要熟悉：

- Python 3.12 的类型标注、dataclass、异常和上下文管理器；
- `async` / `await`、异步迭代器和 `asyncio` 基础；
- FastAPI 路由与依赖注入；
- SQL、事务、索引和 PostgreSQL 基础；
- Docker 的容器、Volume 和网络基础；
- Pydantic 与 SQLAlchemy 2.x 的基本用法。

Celery、Redis lease、Elasticsearch、sqlglot、LangGraph 和多 Agent 编排会在实际使用时讲解，无需提前掌握。

## 如何使用这套讲义

每个实现阶段都按同一条路径推进：

1. **理解问题**：明确当前系统缺少的能力；
2. **写出约束**：列出数据边界、安全边界和必须保持的不变量；
3. **完成最小实现**：先让主流程运行，并通过对应测试；
4. **处理真实边界**：加入并发、失败恢复、资源限制和可观测性；
5. **追踪调用链**：沿 API → Service → Repository → 外部系统复盘代码；
6. **完成验收**：用测试和实际行为证明功能成立。

讲义中的“实现”表示需要创建或修改代码。代码片段用于解释关键抽象，完整字段、错误类型和边界分支以文中标出的源码路径为准。推荐阅读顺序是先按步骤完成实现，再阅读后半章的成品设计讲解。

## 代码、测试与完成态

当前仓库包含项目完成态。学习过程使用课程提供的练习分支，按章节逐步创建 `app/` 中的实现。实现过程中按以下顺序使用仓库材料：

1. 阅读当前步骤给出的接口和不变量；
2. 运行本阶段测试，根据失败信息修正实现；
3. 按文中标出的路径查看完成态源码，比较抽象边界和调用顺序；
4. 回到自己的实现完成测试，记录两种方案的差异。

`conf/`、`docker/` 和依赖清单是课程脚手架；`tests/` 是行为规范；`web/` 用于最终联调；`dbmock/` 用于准备 Doris 练习数据。每章的最小验收通过后即可进入下一章，完整验收对应仓库当前设计。

## 准备开发环境

先按照根目录 [README](../README.md) 创建环境配置，然后执行：

```bash
uv sync
docker compose -f docker/compose.yml up -d
uv run pytest -q
```

后续章节会逐步使用 PostgreSQL、Redis、Elasticsearch、Doris 和 Docker。某个外部服务暂时不可用时，可以先用 Protocol 和 fake 完成 Service 测试，再替换为真实 Repository。
